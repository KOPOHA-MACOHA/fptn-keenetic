# CPU и память: заметки для разработки

Инструмент находится только в `tests/` и не входит в установку, клиент,
службу или панель. Запускается разработчиком для сравнения версий:

```sh
sh tests/profile-resources.sh 60 2
```

60 секунд, интервал 2 секунды. Допустимы 2–3600 секунд и интервал 1–60 секунд.
Команда работает только во время запуска; фонового сборщика нет. Она читает `/proc`,
не создаёт тестового трафика, не перезапускает FPTN и не меняет сеть.

Показываются общий CPU роутера, отдельно CPU клиента и supervisor, RSS каждого
процесса и MemAvailable. Итог содержит среднее и максимум CPU, максимум RSS,
минимум доступной памяти. Среднее CPU взвешено по длине интервалов.
100% означает все логические процессоры вместе. Значения CPU после запуска
или смены процесса появляются со следующего отсчёта: время старого PID не
приписывается новому. Проверяются boot ID, PID и время создания процесса.

RSS включает разделяемые страницы и не равен приватной памяти. Его нельзя
складывать с RSS общего lighttpd и называть памятью FPTN. Сам измеритель и другие
программы попадают в общий CPU; в CPU клиента и supervisor они не входят.
Пики между отсчётами могут быть пропущены. Это не проверка максимальной скорости.

Для сравнения версий нужны одинаковые сервер, стратегия и трафик. Полезны три
фазы: простой после установления обоих туннелей, одинаковая передача данных,
простой после неё. Рост RSS под нагрузкой сам по себе не доказывает утечку:
аллокатор может оставить освобождённую память для повторного использования.

## Изменения 0.18.1

- Проверка живого процесса использует один снимок `/proc/PID/stat` вместо двух;
  boot ID читается встроенным `read` и повторно используется в пределах команды.
  Проверки времени создания, zombie и принадлежности исполняемого файла сохранены.
- Опрос API использует один структурированный снимок состояния. Раньше он дополнительно
  запускал текстовый `fptnctl status` с повторными проверками процессов.
- Клиент, размеры его очередей, число туннелей и зависимости не изменены.

Изолированный микротест на Linux x86_64: 120 проверок живого процесса требовали
360 запусков вспомогательных программ, теперь 120. Три прохода до изменения:
0,411 / 0,463 / 0,427 с; после: 0,127 / 0,126 / 0,147 с.
Это накладные расходы одной операции управления, **не ускорение VPN и не замер
на Keenetic**. Тест можно повторить, передав две доверенные версии контроллера:

```sh
python3 tests/benchmark_service_overhead.py old-fptnctl scripts/fptn-native-service.sh
```

Снижение RSS клиента на реальном роутере пока не подтверждено. Перед изменением
очередей нужны отдельные испытания под нагрузкой с учётом потерь пакетов и скорости.
