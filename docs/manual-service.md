# Ручная служба Entware: первый этап IPv4/CIDR

Используется уже проверенный на Hopper KN-3810 клиент 0.1.0 и статический Brotli
из `/opt/tmp/fptn-connect-test`. Полная пересборка FPTN не требуется.
Это первый вариант службы, проверенный локально с подменой сетевых команд;
реальную пересылку трафика LAN необходимо проверить на роутере.

`fptnctl install /opt/tmp/fptn-connect-test` проверяет SHA256SUMS пакета и копирует
клиент и декодер в `/opt/libexec/fptn`. Сценарий устанавливается как
`/opt/bin/fptnctl`. Существующие настройки сохраняются. Служба не регистрируется
в init.d, cron или netfilter.d: автозапуск выключен.

## Первый запуск

```sh
/opt/bin/fptnctl configure
/opt/bin/fptnctl start
```

Настройка запрашивает скрытый токен, выводит список серверов и предлагает выбрать
номер. Как в успешных испытаниях, используются obfuscation, dual-rolling-tunnel,
SNI google.com и интерфейс fptn0. Встроенные split-tunnel, ad-block и blacklist
выключены. Токен декодируется локально; jq noregex поддерживается.

Затем вводятся публичные IPv4/CIDR через пробел или запятую. Адрес без префикса
означает /32, адрес сети нормализуется, повторы удаляются. Пустой Enter принимает
предложенный список, `-` оставляет его пустым. Для первой настройки предлагается
один IPv4 сервиса api.ipify.org, полученный коротким прямым HTTPS-запросом.
Если сервис недоступен, список пуст. В этом случае туннель может запуститься,
но LAN-трафик через него не направляется. Не заменяйте первый тест большим списком.

Настройки: `/opt/etc/fptn/{token,server,cidrs}`. Каталог 0700, файлы 0600.
Токен доступен root и, как в upstream CLI, передаётся аргументом процесса.
Сценарий не печатает его и не использует shell source/eval для настроек.

После start проверьте `https://api.ipify.org` в браузере телефона в домашнем Wi-Fi
с выключенным VPN-приложением телефона. Если домен разрешился в указанный CIDR,
должен быть виден выход VPN. Непопавший в список адрес продолжит идти обычным
маршрутом. Команды curl на самом роутере в этом варианте остаются вне политики:
правило ограничено входящим LAN-интерфейсом br0, а не отдельным устройством.

## Управление

```sh
fptnctl status
fptnctl logs
fptnctl stop
# Изменение списка/сервера: сначала stop, затем configure и start.
```

Сеанс не ограничен 90 секундами. При выходе клиента supervisor удаляет свои
сетевые правила. Автоматического цикла перезапусков нет. `status` показывает
процессы и факт READY при старте, не гарантирует текущую доступность интернета.

При обычной остановке удаляются только собственные записи. При прерванной очистке
каталог состояния сохраняется, следующий запуск блокируется. `fptnctl recover`
может повторить очистку по журналу после смерти supervisor; он отказывается
работать при живом supervisor. SIGKILL/отключение питания не обрабатываются trap.
После перезагрузки сначала проверяется состояние, затем вручную recover/start.

## Сетевые изменения

- Отдельная таблица **30091**, протокол маршрутов **186**.
- Правила приоритета **61**, `iif br0 to CIDR lookup 30091`: все устройства LAN
  выбираются по адресу назначения. Конфликт приоритета/таблицы блокирует запуск.
- Маршруты CIDR через fptn0; unreachable default в этой таблице препятствует
  возврату к обычным таблицам при исчезновении TUN-маршрута, пока правила активны.
- Отдельные цепочки **FPTN_KN_F** (FORWARD) и **FPTN_KN_N** (POSTROUTING).
  Разрешается выход br0→fptn0 к CIDR и установленный обратный поток;
  MASQUERADE использует адрес TUN. Чужие цепочки и общие таблицы не очищаются.

Основной default route, правила других VPN, DNS, IPv6, системный ip_forward
не меняются. В первом варианте принимаются только IPv4-назначения, не охватывающие
локальные, приватные, CGNAT и multicast/reserved диапазоны. Полного справочника
IANA специальных адресов валидатор не заменяет. IPv6 и доменная маршрутизация
ещё не реализованы. Остановка службы возвращает обычную маршрутизацию;
постоянного kill switch нет.

Интеграция с пересозданием firewall Keenetic и сменой WAN пока отсутствует.
После таких событий нужны status/logs и проверка трафика, при необходимости
stop/start. Пока не включайте автоматический запуск.

## Журналы и проверки

Активный stdout-журнал находится в каталоге состояния. Supervisor раз в 1–2 секунды
обрезает его и собственный активный файл upstream `/var/log/fptn/fptn-client-cli.log`,
если размер превысил 128 КиБ. Это периодическая обрезка, не жёсткий предел размера
между проверками; upstream также имеет собственную ротацию. При остановке
сохраняется хвост stdout до 64 КиБ и журнал supervisor до 16 КиБ в `/opt/etc/fptn`.

Локальные проверки используют stateful-моки ip/iptables и небольшой тестовый ELF:
start/status/stop, выбор сервера и права файлов, валидация CIDR, сохранение чужих
цепочек, откат при ошибке на каждом шаге настройки, повторная очистка и защита
от повторного использования PID (время старта и boot_id). Это не проверка реального VPN или Keenetic firewall.
