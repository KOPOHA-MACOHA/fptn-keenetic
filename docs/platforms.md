# Платформы и границы проверки

**Аппаратные испытания проводились только на Keenetic Hopper (KN-3810).**
Другие модели на физическом оборудовании не проверялись. Это не сертификация
совместимости и не гарантия работоспособности каждого выпуска даже на указанной модели.
CI/QEMU подтверждают только перечисленные ниже автоматические проверки.
Установка и использование выполняются на свой страх и риск; см. [оговорки](../DISCLAIMER.md).

| Пакет | Минимальная ISA / ABI | Проверка |
| --- | --- | --- |
| mipsel-mips32r2-softfloat | MIPS32r2, little-endian, o32, soft-float | Для клиента 0.5.0 — сборка, ELF и QEMU; не гарантия поддержки каждой модели |
| aarch64 | ARMv8-A, little-endian, LP64 | Экспериментальная кросс-сборка; ELF и QEMU пройдены, аппаратной проверки нет |
| armv7-softfloat | ARMv7-A, little-endian, EABI5, базовое соглашение вызова | Экспериментальная кросс-сборка; ELF и QEMU пройдены, аппаратной проверки нет |

Статические musl-бинарники не зависят от версии glibc/libstdc++ Entware.
ARMv7 собирается без обязательных инструкций аппаратного FPU. Это не универсальная
сборка для ARMv6, big-endian ARM или произвольного устройства OpenWrt.
Службе нужны KeeneticOS, Entware и свободный OpkgTun0 (в текущем выпуске номер фиксирован); наличие подходящей
ISA само по себе не подтверждает поддержку модели или производительность.

`ports/targets.json` закрепляет отдельный SDK по digest для каждой ARM-платформы.
`render-platform.py` создаёт отдельный профиль и Dockerfile; исходный MIPS
Dockerfile и его ключ зависимостей не переписываются. OCI-снимки зависимостей
имеют отдельные ключи и сохраняются до компиляции клиента. При изменении только
панели/службы повторной сборки C++ и зависимостей нет.

Сборка проверяет класс ELF, endian, ISA/ABI, отсутствие динамического загрузчика
и библиотек. Под QEMU выполняются C++20, threads/atomic64/exceptions/coroutines,
CLI --help/--version, защитные проверки native-режима, probe-only на закрытом
loopback-порту и сжатие/распаковка тестового Brotli-токена. Эти проверки не являются
живым VPN-подключением или испытанием на физическом ARM-роутере.

Опубликованный `platform-releases.json` содержит точные хеши клиента, декодера,
лицензий и исходников. Запись добавляется только после успешной сборки и проверки
её результатов. Установщик определяет архитектуру по метаданным Entware и для ARM
проверяет `uname -m`; отсутствующий выпуск не заменяется MIPS-пакетом.
Обновления панели сохраняют старый плоский канал для MIPS и выбирают отдельную
запись клиента на ARM. Путь к релизу всегда в том же репозитории, не задаётся
браузером или токеном VPN.

Для GCC 13 на ARM32 BoringSSL выдаёт `stringop-overflow` в
`slhdsa_thash_prfmsg_sha256`, хотя перед циклом стоит проверка
`BSSL_CHECK(config->n <= sizeof(hmac_key))`. Только для этой зависимости и ARM32
предупреждение не считается ошибкой; оно не скрывается, остальные ошибки остаются
фатальными. Проверка границ, криптографические исходники и версии зависимостей
не изменяются.
