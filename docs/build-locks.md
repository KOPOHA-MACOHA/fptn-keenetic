# Закреплённые зависимости сборки

Файлы `build-locks/` относятся только к CI/SDK. На роутер они не устанавливаются.
Версии клиента, протокол, настройки сети и панели эта работа не меняет.

## Что закреплено

- `conan.lock`: точные версии и recipe revisions всех host/build/test требований,
  включая транзитивные зависимости. Локальные BoringSSL и YAFF также закреплены.
- `graph.json`: полный граф рецептов с разделением host/build и связями между ними.
  Проверяется не только наличие верхнеуровневых библиотек.
- `python.txt`: Conan 2.34.0, CMake 3.31.6, Ninja 1.13.2 и весь установленный Python
  граф, включая pip; версии и SHA-256 дистрибутивов. Установка с `--require-hashes`
  и без изолированной среды, способной незаметно скачать новые build requirements.
- `apt.txt`: точные версии установленного Ubuntu build-окружения, включая GCC,
  Python, binutils, QEMU и системные библиотеки.
- `build-profile`: явный профиль сборочной машины вместо повторного autodetect.
- SDK, Ubuntu base и Dockerfile frontend уже закреплены по digest. Conan CMake
  для сборки некоторых зависимостей — отдельный рецепт 4.4.4, он закреплён в lock.

Основа — офлайн-захват реально сохранённых ARM OCI-снимков:
[Actions 42575096123](https://github.com/KOPOHA-MACOHA/fptn-keenetic/actions/runs/42575096123),
коммит `6d873b3cc52524096b9428515d2d88deb5f6866e`.
Оба ARM job успешно извлекли одинаковый граф и версии инструментов без компиляции;
MIPS job обнаружил отсутствие точного Actions cache и остановился без пересборки.
MIPS восстанавливается отдельной проверкой уже с этим lock.
Временные timestamps локальных export исключены: фиксируется revision рецепта,
а не время повторного экспорта тех же исходников.

## Сборка и кеш

`conan install` всегда получает явный lock; `--lockfile-partial` не используется.
После установки и перед компиляцией клиента проверяются источники, инструменты
и граф. Проверка сохранённого образа работает офлайн и не вызывает install/build.
Несовпадение останавливает сборку вместо выбора новых библиотек.

Все значимые lock-файлы входят в ключи кешей MIPS, ARM64 и ARMv7. Только два
конкретных проверенных ARM-снимка разрешено импортировать под новыми ключами:
`cache-imports.json` связывает точный новый ключ, старый ключ и digest OCI.
Нет общего fallback на «похожий» SDK или ABI. Полная проверка OCI и проверка графа
перед компиляцией сохраняются. При любом изменении входов импорт перестаёт подходить.

Подготовленные MIPS-снимки, как и ARM, сохраняются в Releases с метаданными и
SHA-256, отдельно от временного Actions cache. При потере cache используется
постоянная копия; если отсутствуют оба хранилища, разрешена первоначальная сборка
с фиксированными зависимостями. Ошибка доступа/сети не считается cache miss.

`Verify locked dependency images` проверяет все три архитектуры: граф/инструменты,
компиляцию клиента, ABI и офлайн CLI/защитные режимы под QEMU. ARM-зависимости
в этой проверке не компилируются. Это не аппаратное испытание и не VPN-подключение.
Проверочный workflow не публикует новый клиент в пользовательский канал.

## Обновление исходного проекта

При изменении `sources.lock.json` проверка требует явного обновления build locks.
Draft PR оригинального проекта не может незаметно пересчитать граф по свежему
Conan Center. Нельзя обходить ошибку удалением lock или `--lockfile-partial`.

Порядок для сопровождающего:

1. Подготовить новый pinned upstream обычным адаптером и определить необходимые
   изменения библиотек. В отдельной build-среде явно создать новый Conan lock
   с теми же профилями/опциями; это контролируемое обновление, не штатная сборка.
2. Получить `conan graph info --format=json` с новым lock и сформировать контракт
   через `graph_contract` из `scripts/dependency-lock.py`; сверить все изменения.
3. Обновить только необходимые Python/Ubuntu версии, хеши, build-profile и
   `metadata.json` (включая SHA-256 точного файла sources.lock.json).
4. Удалить старые импорты кеша: перенос нового графа на старые библиотеки запрещён.
5. Пройти тесты и сборки всех трёх архитектур, подготовить постоянные снимки.
   Только после проверок выпускать клиент через обычный конвейер публикации.

Если зафиксированный пакет удалён с сервера, чистая сборка завершится ошибкой;
она не заменит его новой версией. Постоянные OCI-снимки снижают зависимость от
каталогов пакетов, но не являются обещанием вечного хранения внешним сервисом.
Фиксация версий не означает побайтовую идентичность ELF: timestamps и поведение
сборочных рецептов требуют отдельной проверки для такого обещания.
