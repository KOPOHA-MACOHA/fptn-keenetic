# Контрольная проверка SmartDNS → ipset Keenetic

На Hopper установлен SmartDNS 46.1, основной DNS :53, `opkg dns-override`.
Штатный FQDN domain-list9 с api.ipify.org не получает динамические адреса,
но добавление двух CIDR в эту же группу успешно направляет LAN через FPTN.
Набор `_NDM_OGDN_4_@domain-list9`: hash:net revision 2, без timeout.

`probe-smartdns-ipset.sh` проверяет способность установленного бинарника SmartDNS
заполнять этот набор. Основной процесс/порт 53, его конфигурация, статистика
клиентов, серверы и `opkg dns-override` не изменяются.

На время до 15 секунд запускается второй foreground SmartDNS на
127.0.0.1:15353 с cache-size 0 и единственным upstream 127.0.0.1:53.
В его отдельной временной конфигурации только одно правило ipset для api.ipify.org.
Кеш/журнал/pid находятся в отдельном mktemp-каталоге.

Два ранее вручную добавленных CIDR 8.6.112.0/32 и 8.47.69.0/32 временно удаляются
через штатный ndmc, затем выполняется nslookup через 127.0.0.1:15353.
Печатаются Members до/после. Возникшие после запроса адреса подтверждают запись
SmartDNS. При завершении/обычном прерывании/ошибке процесса оба исходных CIDR
восстанавливаются; временный процесс останавливается, файлы удаляются.
SIGKILL и отключение питания trap обработать не может.

Это не постоянная схема и не самостоятельная реализация доменной маршрутизации.
Прямые записи в ipset не наполняют внутреннюю DNS-модель ndm; счётчик динамических
FQDN-адресов в GUI может остаться нулевым. Проверяется именно набор ядра.
Набор Keenetic не поддерживает timeout: окончательное решение потребует
управления устаревшими адресами и пересозданием наборов, а также синхронизации
доменных списков. Имена наборов являются деталями реализации Keenetic.

Локальные тесты используют моки: успешный запрос, ошибка запроса, ошибка запуска,
остановка процесса, возврат исходных CIDR и очистка файлов. Реальное заполнение
набора ядра проверяется только выполнением сценария на роутере.

Синтаксис ipset подтверждён в [SmartDNS Release46.1](https://github.com/pymumu/smartdns/blob/Release46.1/etc/smartdns/smartdns.conf).
Entware 46.1 устанавливает бинарник и S38smartdns из [официального пакета](https://github.com/Entware/entware-packages/blob/master/net/smartdns/Makefile).
