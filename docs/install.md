# Установка, обновление и удаление FPTN

> **Установка и использование — на свой страх и риск.** Проект экспериментальный.
> Аппаратные испытания проводились только на Keenetic Hopper (KN-3810).
> На других моделях работа не подтверждена. Возможны потеря связи и простои;
> заранее сохраните конфигурацию и обеспечьте локальный доступ для восстановления.

## Поддерживаемая платформа

Доступные архитектуры перечислены в [таблице платформ](platforms.md).
Основная — Entware **mipsel / mips32r2 / soft-float**, включая `mipsel-3.4`
и `mipsel-3.4_kn`. ARM64/ARMv7 добавляются в каталог только
после успешных проверок их собственных статических бинарников под QEMU.
Название `arch: mips` в Keenetic CLI не означает big-endian Entware.
Установщик читает `entware_release` как данные, дополнительно сверяет ядро ARM,
проверяет описание и SHA256 клиента. Неизвестная архитектура или отсутствующий
выпуск приводят к отказу, без загрузки «похожего» бинарника.

Нужны **KeeneticOS 5.0 или новее с поддержкой OpkgTun**, установленный Entware,
компонент TUN (`/dev/net/tun`) и `ndmc`. Если прошивка не позволяет создать
штатный OpkgTun, установка невозможна; KeeneticOS 4.x и старее не поддерживаются.
[Источник требования](../README.md#требования-и-платформы).
Bootstrap устанавливает только недостающие утилиты и пакеты: curl, jq, ip-full,
lighttpd с CGI/setenv-модулями и PHP CGI, а также используемые командами службы
пакеты coreutils, net-tools-netstat, tar и gzip. Уже доступные команды при ручной
установке не заменяются. IPK явно объявляет необходимые пакеты в `Depends`.
Пакеты берутся из настроенных репозиториев Entware; `opkg upgrade` не вызывается.
Пакеты OpenWrt, компиляторы и Conan на роутер не устанавливаются.
Установка пакетов Entware выполняется до транзакции FPTN и при её откате не отменяется.
Проверено наличие пакетов в [официальном списке Entware](https://bin.entware.net/mipselsf-k3.4/Packages.html).

## Онлайн-установка одной командой

В SSH-консоли Entware от root выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/get.sh | sh
```

При отсутствии curl: `opkg update && opkg install curl ca-certificates`.
`get.sh` полностью загружает bootstrap во временный закрытый каталог и затем
запускает его. Временные файлы удаляются после завершения. Если загрузка
bootstrap завершается ошибкой, он не исполняется.

Bootstrap читает канал `web/update.json`, загружает установщик выпуска по полному
SHA и автоматически проверяет SHA256. Файлы, клиент и декодер выбираются из одного
закреплённого выпуска и проверяются установщиком. Ручная загрузка архивов и
ручная сверка контрольных сумм не нужны. На роутере ничего не компилируется.

По умолчанию LAN IPv4 — `192.168.1.1`. Для другого адреса:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/get.sh | sh -s -- 192.168.0.1
```

Установщик предложит TCP-порт **1111**. Enter проверяет и выбирает предложенный
порт; можно ввести свой номер от 1 до 65535. Если он занят, установщик предлагает
следующий номер, сохраняя возможность ввести любой другой. Чужой сервис не
останавливается. При повторной установке предлагается сохранённый порт.
Ввод читается из терминала, поэтому работает и с `curl … | sh`.

Без терминала задайте LAN и порт явно:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/get.sh | sh -s -- 192.168.1.1 1111
```

Если явно выбранный порт занят, установка завершается с понятной ошибкой.
Фоновое обновление использует сохранённый порт без запросов.

## Ручная установка из полного архива

Скачайте архив своей архитектуры из выпуска `runtime-COMMIT`, перенесите его
на роутер и распакуйте. В каталоге `fptn-keenetic` выполните:

```sh
sh install.sh install
```

При другом адресе LAN: `sh install.sh install 192.168.0.1`.
Без терминала: `sh install.sh install 192.168.0.1 1111`.
Установщик сам проверит комплект по `SHA256SUMS`. В пакет входят клиент, Brotli,
лицензии, панель и служба; файлы FPTN повторно не загружаются. Для недостающих
системных пакетов может потребоваться доступ к репозиториям Entware.
Архив не содержит токенов или учётных данных.

Установщик выводит адрес панели с выбранным портом. Пример при значениях по умолчанию:
**http://192.168.1.1:1111/**. При другом LAN IPv4 укажите его аргументом.
Используется существующий root-lighttpd и его обычный Entware init-скрипт.
Его основной конфиг должен подключать `conf.d/*.conf`. Если lighttpd до этого
не был установлен, bootstrap добавляет `05-fptn-bootstrap.conf`: начальный
слушатель нового Entware lighttpd переносится с порта 80 на свободный локальный TCP-порт, начиная с **127.0.0.1:1110**,
чтобы не конфликтовать с веб-интерфейсом Keenetic. Пользователь открывает только
LAN:выбранный-порт. С версии 0.18.13 это применяется и к заранее установленному,
но ещё не работающему lighttpd: только если основной конфиг совпадает с контрольной
суммой пакета opkg, а основной порт равен 80, включая неуказанное значение по умолчанию.
Пользовательские конфиги, другой основной порт и работающий lighttpd не перенастраиваются.
У действующего lighttpd этот фрагмент не создаётся. Настройка начального
слушателя остаётся с общим пакетом lighttpd после удаления FPTN. Чужой `95-fptn.conf`, занятый
порт, rootless lighttpd и неизвестные остатки установки приводят к понятной ошибке;
установщик не переписывает настройки общего веб-сервера.

После установки:

1. В браузере создайте учётную запись панели либо используйте root Entware.
2. В открытом разделе токена вставьте свой токен, нажмите «Прочитать серверы»,
   выберите сервер/автовыбор и сохраните настройки. Токен не возвращается в браузер.
3. Установщик создаёт первый свободный **OpkgTun**, проверяя объекты Keenetic
   и устройства Linux. Уже выбранный собственный интерфейс сохраняется.
   После новой установки нажмите в панели «Сохранить конфигурацию Keenetic»:
   это сохранит и другие текущие несохранённые изменения Keenetic.
   До этого новый интерфейс существует только в running-config.
4. Нажмите «Запустить». Назначьте нужные CIDR/домены интерфейсу FPTN в Keenetic.
   При необходимости включите автозапуск отдельной кнопкой.

Установка сама не создаёт VPN-подключение и не включает автозапуск.
По умолчанию она не меняет DNS, маршруты, firewall и основной выход в интернет.
Отдельная экспериментальная настройка IPv6 добавляет только собственный адрес
собственного OpkgTun и ограниченный этим интерфейсом NAT66; см. [IPv6](release-0.15.md).
Чужие OpkgTun не присваиваются FPTN и не перенастраиваются. При ошибке новой
настройки удаляется только созданный этой попыткой интерфейс. Если прошивка
не поддерживает создание выбранного номера, установка прекращается.

## Обновление действующей службы

Для установленной версии используйте «Проверить обновления» → «Установить обновление».
Тот же установщик поддерживает и старую установленную службу, и состояние до ввода
первого токена. Настройки входа, токен, сервер, избранные, исключения, параметры
подключения и автозапуск сохраняются. Если клиент и управляющий supervisor не изменились, службу не
перезапускают, клиент не скачивается заново. Изменённый supervisor перезапускается
с сохранением прежнего состояния даже при том же ELF; иначе его старый код
продолжал бы работать в памяти до ручного перезапуска. При необходимости замены ELF проверяются
контрольная сумма и совместимость сохранённых параметров; прежний работающий
клиент перезапускается, а при ошибке выполняется откат.

Проверяется реальный ответ HTML и API lighttpd. Сообщение `failed` от init само
по себе не означает неудачную установку. Совместные панели на короткое время
недоступны при перезапуске общего lighttpd.

Код и конфигурация живут в `/opt/bin`, `/opt/libexec/fptn`, `/opt/share/fptn-web`,
`/opt/etc/fptn`; `/opt/tmp` используется только для загрузки и проверки.
Клиент и декодер закреплены по SHA256, описания оригинальных исходников и лицензии
входят в пакет. Смена версии панели не запускает компиляцию зависимостей.

## Удаление

После установки/обновления до 0.13.0:

```sh
fptnctl uninstall
```

Команда проверяет владение файлами и отсутствие операции панели, останавливает
собственные процессы и удаляет программу, панель, её фрагмент lighttpd и свой
автозапуск, hook восстановления IPv6 и собственную цепочку NAT66. Неизвестные
правила не очищаются; если удалить собственную цепочку безопасно нельзя,
удаление программы прекращается с сохранением файлов. PHP, lighttpd и прочие общие пакеты Entware остаются. Чужие файлы в
каталогах программы и панели не удаляются. Если они остались в `libexec/fptn`, переустановка остановится
с сообщением о существующем каталоге, пока пользователь не разберёт эти файлы.

Начиная с 0.18.10 это **полное удаление**: `/opt/etc/fptn` вместе с токеном,
учётными данными панели, настройками и всеми собственными резервными копиями,
сессии, кэш, журналы клиента и собственная запись package feed удаляются.
Временные копии прежнего токена тоже удаляются. Неизвестные файлы в каталоге
настроек удаляются вместе с ним; не храните в нём данные других приложений.
Каталоги скачанных вручную архивов вне управляемой установки не затрагиваются.

Сохранённый собственный OpkgTun удаляется после проверки идентификатора, типа,
описания и адреса. При несовпадении удаление прекращается, чтобы не затронуть
переиспользованный чужой интерфейс. Другие OpkgTun не удаляются.
**Команда сохраняет весь running-config Keenetic**, чтобы удалённый интерфейс
не появился после перезагрузки. Это также сохраняет остальные текущие изменения
конфигурации. При ошибке удаления или сохранения данные остаются для повторной попытки.
Доменные/CIDR-списки и правила внешних менеджеров не принадлежат FPTN: при необходимости
переназначьте или удалите их в программе, которой они были созданы.

lighttpd используется совместно ради экономии ОЗУ. Его пакет, основная
конфигурация и общий bootstrap-listener остаются: от них могут зависеть другие
панели Entware. Удаляется только фрагмент FPTN `95-fptn.conf`, закрывающий порт панели.
Отдельный процесс дал бы независимые перезапуски, но потребовал бы дополнительной памяти.

## Проверки и границы

Actions проверяет транзакции установки/отката, начальную настройку, вход и настоящий
lighttpd, блокировки операций, удаление, контрольные суммы и состав архива.
Версии клиентов и результаты их ELF/ABI, CLI и QEMU-проверок указаны в выпусках.
Выбор порта проверяется с настоящим терминалом, выбор интерфейса и откат —
с изолированными моделями прошивки. Это не аппаратная проверка новой установки.
Аппаратные результаты предыдущих версий не подтверждают все возможности новых выпусков.
Новые WAN/PPPoE и IPv6 проверены отдельными сетевыми автотестами Linux, включая
запрос/ответ LAN и восстановление NAT. Физически чистая установка на роутер,
живой IPv6 VPN и аппаратная эксплуатация ARM этим не подтверждаются.
Границы проверки указываются отдельно от списка реализованных возможностей.


## Пакетный способ

Альтернатива обычному bootstrap и `.tar.gz` — [пакет Entware `.ipk`](opkg.md):
автоматическая регистрация feed, `opkg install/upgrade/remove` и обновление
из панели через тот же пакетный менеджер.

## Внешние команды и зависимости (0.18.12)

| Назначение | Команды | Пакеты Entware |
| --- | --- | --- |
| Ограничение времени, приоритет, фоновый запуск | `timeout`, `nice`, `nohup` | `coreutils-timeout`, `coreutils-nice`, `coreutils-nohup` |
| Чтение токена и скрытый ввод в CLI | `base64`, `stty` | `coreutils-base64`, `coreutils-stty` |
| Проверка файлов и путей | `stat`, `readlink`, `sha256sum`, `md5sum`, `mktemp` | соответствующие `coreutils-*` |
| Проверка занятости порта | `netstat` | `net-tools-netstat` |
| Распаковка runtime из IPK | `tar`, `gzip` | `tar`, `gzip` |
| HTTPS, JSON, сетевые снимки | `curl`, `jq`, `ip` | `curl`, `jq`, `ip-full` |
| Панель и её локальные обработчики | lighttpd, PHP CGI | `lighttpd`, `lighttpd-mod-cgi`, `lighttpd-mod-setenv`, `php8-cgi` |

Базовые команды POSIX/BusyBox (например, `awk`, `grep`, `head`, `tail`, `tr`,
`wc`, `pidof` и файловые операции) предоставляет KeeneticOS. Их наличие проверяется
до развёртывания FPTN с указанием конкретной недостающей команды.
Короткий загрузчик `get.sh` отдельно проверяет `curl`, `mktemp`, `rm` и `sh`,
которые нужны ему ещё до запуска полного bootstrap.

CA bundle подтягивается зависимостями Entware curl/libcurl. Команда `openssl`,
Python, дополнительные JSON-модули PHP, отдельный NTP-клиент и системная библиотека Brotli не нужны:
PHP использует свои встроенные функции, NTP и TLS входят в клиент, а декодер
Brotli поставляется готовым статическим бинарником.

`ip6tables` и поддержка NAT66 ядром нужны только при явном включении IPv6.
Они не устанавливаются как обязательная зависимость IPv4-клиента. `logger`
используется только при наличии. Старые диагностические сценарии DNS и первые
прототипы не входят в рабочую установку; их инструменты не нужны службе.

CI сверяет карту пакетов bootstrap с IPK и командами preflight службы/установщика,
а также проверяет установку при поочерёдном отсутствии внешних утилит.

Локальные HTTP-проверки установки и смены порта игнорируют пользовательский
`.curlrc`, используют IPv4 и обходят прокси. Это не меняет настройки curl
для загрузки файлов из интернета. При неудаче проверочный curl выводит свою
ошибку при установке и сохраняет её в `http-diagnostic/curl-error` до отката.
Проверки версии страницы, ответа API 401 и готовности PHP остаются обязательными.
