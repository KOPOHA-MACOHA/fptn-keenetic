# Установка, обновление и удаление FPTN

> **Установка и использование — на свой страх и риск.** Проект экспериментальный.
> Аппаратные испытания проводились только на Keenetic Hopper (KN-3810).
> На других моделях работа не подтверждена. Возможны потеря связи и простои;
> заранее сохраните конфигурацию и обеспечьте локальный доступ для восстановления.

## Поддерживаемая платформа

Доступные архитектуры перечислены в [таблице платформ](platforms.md).
Основная — Entware **mipsel / mips32r2 / soft-float**, включая `mipsel-3.4`
и `mipsel-3.4_kn`. ARM64/ARMv7 добавляются в каталог только
после успешных проверок их собственных статических бинарников под QEMU.
Название `arch: mips` в Keenetic CLI не означает big-endian Entware.
Установщик читает `entware_release` как данные, дополнительно сверяет ядро ARM,
проверяет описание и SHA256 клиента. Неизвестная архитектура или отсутствующий
выпуск приводят к отказу, без загрузки «похожего» бинарника.

Нужны установленный Entware, компонент TUN (`/dev/net/tun`) и `ndmc` KeeneticOS.
Bootstrap устанавливает только недостающие пакеты: curl, jq, ip-full, lighttpd,
его CGI/setenv-модули и PHP CGI, если нет уже установленного PHP.
Пакеты берутся из настроенных репозиториев Entware; `opkg upgrade` не вызывается.
Пакеты OpenWrt, компиляторы и Conan на роутер не устанавливаются.
Установка пакетов Entware выполняется до транзакции FPTN и при её откате не отменяется.
Проверено наличие пакетов в [официальном списке Entware](https://bin.entware.net/mipselsf-k3.4/Packages.html).

## Онлайн-установка одной командой

В SSH-консоли Entware от root выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/get.sh | sh
```

При отсутствии curl: `opkg update && opkg install curl ca-certificates`.
`get.sh` полностью загружает bootstrap во временный закрытый каталог и затем
запускает его. Временные файлы удаляются после завершения. Если загрузка
bootstrap завершается ошибкой, он не исполняется.

Bootstrap читает канал `web/update.json`, загружает установщик выпуска по полному
SHA и автоматически проверяет SHA256. Файлы, клиент и декодер выбираются из одного
закреплённого выпуска и проверяются установщиком. Ручная загрузка архивов и
ручная сверка контрольных сумм не нужны. На роутере ничего не компилируется.

По умолчанию LAN IPv4 — `192.168.1.1`. Для другого адреса:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/get.sh | sh -s -- 192.168.0.1
```

**Порт панели текущего выпуска фиксирован: 1111.** При занятом чужом порте
установка прекращается. Интерактивный выбор и предложение следующего порта
[запланированы](roadmap.md), но ещё не реализованы.

## Ручная установка из полного архива

Скачайте архив своей архитектуры из выпуска `runtime-COMMIT`, перенесите его
на роутер и распакуйте. В каталоге `fptn-keenetic` выполните:

```sh
sh install.sh install
```

При другом адресе LAN: `sh install.sh install 192.168.0.1`.
Установщик сам проверит комплект по `SHA256SUMS`. В пакет входят клиент, Brotli,
лицензии, панель и служба; файлы FPTN повторно не загружаются. Для недостающих
системных пакетов может потребоваться доступ к репозиториям Entware.
Архив не содержит токенов или учётных данных.

Адрес панели — **http://192.168.1.1:1111/**, при другом LAN IPv4 укажите его аргументом.
Используется существующий root-lighttpd и его обычный Entware init-скрипт.
Его основной конфиг должен подключать `conf.d/*.conf`. Если lighttpd до этого
вообще не был установлен, bootstrap добавляет `05-fptn-bootstrap.conf`: начальный
слушатель нового Entware lighttpd переносится с порта 80 на **127.0.0.1:1110**,
чтобы не конфликтовать с веб-интерфейсом Keenetic. Пользователь открывает только
LAN:1111. У действующего lighttpd этот фрагмент не создаётся. Настройка начального
слушателя остаётся с общим пакетом lighttpd после удаления FPTN. Чужой `95-fptn.conf`, занятый
порт, rootless lighttpd и неизвестные остатки установки приводят к понятной ошибке;
установщик не переписывает настройки общего веб-сервера.

После установки:

1. В браузере создайте учётную запись панели либо используйте root Entware.
2. В открытом разделе токена вставьте свой токен, нажмите «Прочитать серверы»,
   выберите сервер/автовыбор и сохраните настройки. Токен не возвращается в браузер.
3. Если интерфейса ещё нет, нажмите «Создать и сохранить интерфейс FPTN».
   Текущий выпуск использует только **OpkgTun0**. Если он занят другим приложением,
   установка откажется продолжать; автоматического выбора следующего номера нет.
   Кнопка также сохраняет текущую конфигурацию Keenetic,
   включая другие несохранённые изменения; это указано рядом с кнопкой.
4. Нажмите «Запустить». Назначьте нужные CIDR/домены интерфейсу FPTN в Keenetic.
   При необходимости включите автозапуск отдельной кнопкой.

Установка сама не создаёт VPN-подключение и не включает автозапуск.
По умолчанию она не меняет DNS, маршруты, firewall и основной выход в интернет.
Отдельная экспериментальная настройка IPv6 добавляет только собственный адрес
OpkgTun0 и ограниченный этим интерфейсом NAT66; см. [IPv6](release-0.15.md).
Чужой OpkgTun0 не присваивается FPTN. Создание собственного интерфейса выполняется
только отдельной командой пользователя, после установки.

## Обновление действующей службы

Для установленной версии используйте «Проверить обновления» → «Установить обновление».
Тот же установщик поддерживает и старую установленную службу, и состояние до ввода
первого токена. Настройки входа, токен, сервер, избранные, исключения, параметры
подключения и автозапуск сохраняются. Если клиент и управляющий supervisor не изменились, службу не
перезапускают, клиент не скачивается заново. Изменённый supervisor перезапускается
с сохранением прежнего состояния даже при том же ELF; иначе его старый код
продолжал бы работать в памяти до ручного перезапуска. При необходимости замены ELF проверяются
контрольная сумма и совместимость сохранённых параметров; прежний работающий
клиент перезапускается, а при ошибке выполняется откат.

Проверяется реальный ответ HTML и API lighttpd. Сообщение `failed` от init само
по себе не означает неудачную установку. Совместные панели на короткое время
недоступны при перезапуске общего lighttpd.

Код и конфигурация живут в `/opt/bin`, `/opt/libexec/fptn`, `/opt/share/fptn-web`,
`/opt/etc/fptn`; `/opt/tmp` используется только для загрузки и проверки.
Клиент и декодер закреплены по SHA256, описания оригинальных исходников и лицензии
входят в пакет. Смена версии панели не запускает компиляцию зависимостей.

## Удаление

После установки/обновления до 0.13.0:

```sh
fptnctl uninstall
```

Команда проверяет владение файлами и отсутствие операции панели, останавливает
собственные процессы и удаляет программу, панель, её фрагмент lighttpd и свой
автозапуск, hook восстановления IPv6 и собственную цепочку NAT66. Неизвестные
правила не очищаются; если удалить собственную цепочку безопасно нельзя,
удаление программы прекращается с сохранением файлов. PHP, lighttpd и прочие общие пакеты Entware остаются. Чужие файлы в
каталогах не удаляются. Если они остались в `libexec/fptn`, переустановка остановится
с сообщением о существующем каталоге, пока пользователь не разберёт эти файлы.

**Токен, вход, настройки и резервные копии остаются в `/opt/etc/fptn`** для
переустановки. **OpkgTun0 и маршруты Keenetic остаются**: переназначьте или удалите
их в Keenetic самостоятельно. Команда не сохраняет и не переписывает firmware-конфиг.
Это позволяет не удалить случайно чужие доменные списки или связанные маршруты.

## Проверки и границы

Actions проверяет транзакции установки/отката, начальную настройку, вход и настоящий
lighttpd, блокировки операций, удаление, контрольные суммы и состав архива.
Клиент 0.5.0 собран и проверен по ELF/ABI, CLI и probe-only под QEMU.
Аппаратные результаты предыдущих версий не подтверждают все возможности новых выпусков.
Новые WAN/PPPoE и IPv6 проверены отдельными сетевыми автотестами Linux, включая
запрос/ответ LAN и восстановление NAT. Физически чистая установка на роутер,
живой IPv6 VPN и аппаратная эксплуатация ARM этим не подтверждаются.
Границы проверки указываются отдельно от списка реализованных возможностей.
