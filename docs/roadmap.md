# План развития

## Выполнено в исходниках 0.16.0

- Автоматический выбор первого свободного OpkgTun при установке; сохранение номера
  при переустановке и обновлении. Номер используется клиентом, службой, MTU,
  IPv6/NAT66, панелью и исходящими проверками.
- Выбор TCP-порта через терминал, в том числе при `curl … | sh`: по умолчанию 1111,
  при конфликте следующий номер, на каждом шаге разрешён свой номер.
- Явный порт для установки без терминала. Фоновое обновление сохраняет адрес и порт.
- Проверки занятости до применения, защита чужих интерфейсов и слушателей, откат
  незавершённой настройки. Новая конфигурация Keenetic сохраняется по отдельной
  команде пользователя, чтобы не записать посторонние ожидающие изменения.
- Автотесты выбора номера, конфликтов порта, TTY-ввода, обновления и отката.

Публикация в канале обновлений выполняется после сборок и проверок. Автотесты
и эмуляция не заменяют испытания на всех моделях роутеров.

## Выполнено в исходниках 0.17.0 / клиент 0.7.0

- Предпочтительный сервер и фактическое подключение показаны отдельно; причина и
  время последнего подключения, время следующей отложенной попытки.
- Настраиваемая проверка передачи IPv4/UDP внутри существующего FPTN-туннеля:
  интервал 30–3600 секунд (по умолчанию 60), тайм-аут 2–15 секунд (5),
  порог 2–10 неудачных циклов (3), отключение в панели.
  Резервная цель используется только при отказе основной. После достижения порога
  нужен успешный контрольный ответ через исходящий интерфейс; иначе результат
  неопределённый и проверка не заставляет перебирать серверы.
- Восстановление сохраняет приоритет избранных и исключения. Устойчивый сервер,
  который только что отказал, временно исключается также из резервного плана.
- Смена TCP-порта в UI без остановки VPN: старый адрес остаётся на время
  подтверждения нового адреса. Нет подтверждения или новая панель недоступна —
  откат. Предусмотрено восстановление незавершённой смены после потери питания.
- Обезличенный диагностический JSON с явным списком полей; без журналов, имён
  и адресов серверов, токена, учётных данных или полного конфига роутера.
  Журналы службы уже ограничены по размеру.

Изменения включены в канал обновлений 0.17.0 после CI и сборок для MIPS, ARM64 и ARMv7.
Проверка UDP не является проверкой всех сайтов, максимальной скорости или IPv6.
Новые сценарии не объявляются проверенными на физических ARM-роутерах.

## Автоматизация выпусков

- После успешных проверок `main` конвейер проверяет артефакты MIPS, ARM64 и ARMv7,
  идентичность исходников, версии и контрольные суммы.
- При изменении клиента сам готовит закреплённые манифесты обычным коммитом,
  явно запускает проверку и упаковку этого SHA, затем обновляет канал.
- Изменения панели используют закреплённые бинарники; изменения только CI или
  документации не предлагают пользователям лишнее обновление.
- Старые, неполные и неподходящие сборки, downgrade и перемещение `main`
  останавливают публикацию. Проверки исходного проекта остаются отдельными PR.

Порядок работы и восстановление: [автоматизация выпусков](release-publication.md).

## Фиксация зависимостей сборки

- Закреплены полный host/build граф Conan с recipe revisions, инструменты Python
  с хешами, системные build-пакеты Ubuntu и профиль сборочной машины.
- Перед компиляцией проверяются источники, граф и инструменты сохранённого OCI.
- MIPS получает постоянную копию снимка в Releases, как ARM.
- Отдельный CI проверяет все три архитектуры; пользовательский runtime не меняется.

Подробности: [build locks](build-locks.md).

## Пакетный канал Entware

- Пакет Entware `.ipk` и отдельные feeds для трёх архитектур реализованы;
  lifecycle, целостность и установка/обновление/удаление проверяются в CI.
  См. [пакетный способ](opkg.md).

Остаются испытания на дополнительном оборудовании и исправления по результатам эксплуатации.

## Следующие улучшения

1. **Фоновый опрос панели — реализовано в 0.18.5.**
   При стабильной работе состояние запрашивается раз в 20 секунд,
   во время операций и переподключения — раз в 2 секунды,
   после потери связи с API — раз в 10 секунд.
   Скрытая вкладка не держит таймер опроса; возврат обновляет состояние сразу.
   Неизменившийся ответ не перерисовывает блоки панели; показ ОЗУ обновляется
   отдельно. Запросы состояния не накладываются, старый ответ не завершает
   новую команду. Журнал по-прежнему загружается по кнопке.
   Это сокращение числа запросов, не измерение CPU или памяти на роутере.

2. **Хранение резервных копий — реализовано в 0.18.8.**
   После подтверждённой установки сохраняются три последних успешных копии
   и все копии, на которые ссылается восстановление. Незавершённые, неудачные,
   старые без журнала и чужие каталоги сохраняются. Порядок определяется
   счётчиком установок, а не часами роутера. Очистка не переходит по символьным
   ссылкам и не пересекает точки монтирования. Ошибка обслуживания копий
   не откатывает успешную установку. Токен и действующие настройки не удаляются.
   Это ограничение расхода накопителя, не заявление об уменьшении ОЗУ.

3. **Получение изменений оригинала — реализовано.**
   Draft PR включает настоящий merge исходников с сохранением истории.
   До слияния проверяются MIPS, ARM64, ARMv7 и runtime. Обновления только кода
   повторно используют проверенные SDK; изменения зависимостей требуют явного
   пересмотра locks. Автоматического слияния и установки нет.
   См. [обновления оригинала](upstream-updates.md).

4. **Дальнейшая оптимизация клиента по подтверждённым измерениям.**
   Сравнивать CPU и ОЗУ до и после изменения в одинаковых сценариях.
   Использовать временные средства измерения и воспроизводимые проверки;
   не добавлять постоянный измеритель в устанавливаемую службу.
   Принимать изменения при подтверждённом выигрыше без ухудшения соединения
   и восстановления. Разделять результаты CI и аппаратные наблюдения:
   показатели CI не объявлять измерениями на роутере.

Остаются измеряемая оптимизация клиента и расширение аппаратной проверки.

### Исправление автозапуска после перезагрузки — 0.18.6

- Состояние в `/opt/var/run` может сохраняться после перезагрузки. Перед запуском служба сравнивает boot ID в PID-файлах с текущей загрузкой ядра, сохраняет журналы и удаляет только подтверждённое состояние предыдущей загрузки.
- Состояние текущей загрузки, смешанные PID-файлы и неизвестные записи автоматически не удаляются; процессы по старым PID не завершаются.
