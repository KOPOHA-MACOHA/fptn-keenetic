# План развития

## Выполнено в исходниках 0.16.0

- Автоматический выбор первого свободного OpkgTun при установке; сохранение номера
  при переустановке и обновлении. Номер используется клиентом, службой, MTU,
  IPv6/NAT66, панелью и исходящими проверками.
- Выбор TCP-порта через терминал, в том числе при `curl … | sh`: по умолчанию 1111,
  при конфликте следующий номер, на каждом шаге разрешён свой номер.
- Явный порт для установки без терминала. Фоновое обновление сохраняет адрес и порт.
- Проверки занятости до применения, защита чужих интерфейсов и слушателей, откат
  незавершённой настройки. Новая конфигурация Keenetic сохраняется по отдельной
  команде пользователя, чтобы не записать посторонние ожидающие изменения.
- Автотесты выбора номера, конфликтов порта, TTY-ввода, обновления и отката.

Публикация в канале обновлений выполняется после сборок и проверок. Автотесты
и эмуляция не заменяют испытания на всех моделях роутеров.

## Выполнено в исходниках 0.17.0 / клиент 0.7.0

- Предпочтительный сервер и фактическое подключение показаны отдельно; причина и
  время последнего подключения, время следующей отложенной попытки.
- Настраиваемая проверка передачи IPv4/UDP внутри существующего FPTN-туннеля:
  интервал 30–3600 секунд (по умолчанию 60), тайм-аут 2–15 секунд (5),
  порог 2–10 неудачных циклов (3), отключение в панели.
  Резервная цель используется только при отказе основной. После достижения порога
  нужен успешный контрольный ответ через исходящий интерфейс; иначе результат
  неопределённый и проверка не заставляет перебирать серверы.
- Восстановление сохраняет приоритет избранных и исключения. Устойчивый сервер,
  который только что отказал, временно исключается также из резервного плана.
- Смена TCP-порта в UI без остановки VPN: старый адрес остаётся на время
  подтверждения нового адреса. Нет подтверждения или новая панель недоступна —
  откат. Предусмотрено восстановление незавершённой смены после потери питания.
- Обезличенный диагностический JSON с явным списком полей; без журналов, имён
  и адресов серверов, токена, учётных данных или полного конфига роутера.
  Журналы службы уже ограничены по размеру.

Изменения включены в канал обновлений 0.17.0 после CI и сборок для MIPS, ARM64 и ARMv7.
Проверка UDP не является проверкой всех сайтов, максимальной скорости или IPv6.
Новые сценарии не объявляются проверенными на физических ARM-роутерах.

## Автоматизация выпусков

- После успешных проверок `main` конвейер проверяет артефакты MIPS, ARM64 и ARMv7,
  идентичность исходников, версии и контрольные суммы.
- При изменении клиента сам готовит закреплённые манифесты обычным коммитом,
  явно запускает проверку и упаковку этого SHA, затем обновляет канал.
- Изменения панели используют закреплённые бинарники; изменения только CI или
  документации не предлагают пользователям лишнее обновление.
- Старые, неполные и неподходящие сборки, downgrade и перемещение `main`
  останавливают публикацию. Проверки исходного проекта остаются отдельными PR.

Порядок работы и восстановление: [автоматизация выпусков](release-publication.md).
