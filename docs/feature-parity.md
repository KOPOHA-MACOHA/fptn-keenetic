# Совместимость с оригинальным FPTN и развитие Keenetic-службы

База сравнения: оригинальный FPTN 0.4.6, закреплённый SHA
`a389bee62da930807c3bc85284ee4976e9c7e08f`; CLI и
`deploy/openwrt/data/files/etc/init.d/fptn`, конфигурация и LuCI main.js
из этого же коммита. Сравнение относится к роутерной службе, а не к переносимости
графического интерфейса Android/Windows.

| Функция оригинала | Keenetic-служба | Состояние |
| --- | --- | --- |
| Токен и список серверов, включая Brotli-токены | Исходный клиент + импорт через панель | Есть |
| Ручной сервер и автоматический выбор | Исходная авторизация + ограниченный выбор | Есть |
| Обфускация TLS и профили подмены SNI | Исходные реализации; список из установленного клиента | Есть; динамический список с 0.11.0 |
| Одинарный, двойной и тройной скользящий туннель | Исходные реализации | Есть |
| Произвольный SNI | Поле в панели | Есть |
| MTU туннеля | Значение из Keenetic либо явное значение через firmware API | Панель 0.10.0 |
| Исходящий интерфейс | Авто либо системное имя; IPv4 default/via в main | Клиент 0.5.0 / служба 0.14.0: PPP без via, привязка сокетов и смена WAN |
| Автозапуск, остановка, перезапуск, восстановление процесса | Entware init + supervisor | Есть; длительная эксплуатация требует проверки |
| Журнал и состояние подключения | Панель и fptnctl | Есть |
| DNS через VPN / свой DNS | Настройки DNS Keenetic/SmartDNS | Сохранена внешняя настройка; помощник подключения VPN DNS не реализован |
| Split tunneling по доменам и CIDR | Штатная маршрутизация Keenetic к OpkgTun0 | Подтверждено на устройстве |
| Блокировка рекламы и доменов | SmartDNS / фильтры Keenetic | Встроенный список FPTN отключён; настройка в соответствующем сервисе |
| IPv6 через VPN | Собственный адрес OpkgTun0 через ndmc + NAT66 только для этого интерфейса | Экспериментально, по умолчанию выключено; 0.15.0 |
| Выбор произвольного TUN | Выделенный OpkgTun0 под контролем Keenetic | Текущее ограничение порта |
| Задержка серверов | Реальное время входа FPTN по кнопке | Есть; это не TCP/ICMP ping оригинального LuCI |
| Обновление | Проверяемые выпуски форка через панель, новые оригинальные версии через PR | Есть |
| Избранные и исключённые серверы, резервные методы | Дополнение форка, выключаемое пользователем | Есть |

OpenWrt UI оригинала в этой версии имеет ручной SNI и браузерные профили.
Отдельного автопоиска SNI или режима под названием REALITY в нём нет.
Функции других платформ нужно сравнивать по их реальному коду отдельно.

## Принципы реализации

1. Транспорт, TLS/маскировка, авторизация, форматы пакетов и скользящие туннели
   остаются в исходном FPTN. Для Keenetic нужны адаптеры TUN и службы, а не
   отдельная реализация протокола.
2. Keenetic владеет интерфейсом и маршрутизацией. Необязательный IPv6 NAT66
   ограничен собственной цепочкой и выходом opkgtun0; другие правила firewall
   не изменяются. MTU явно заданной
   конфигурации применяется только к принадлежащему FPTN OpkgTun0 через ndmc;
   автоматический MTU просто читается. DNS сохраняет выбранную пользователем схему.
3. Панель вызывает фиксированные операции службы. Настройки остаются JSON-данными,
   не shell-кодом; вход и секреты хранятся отдельно от document root.
4. Изменение ожидаемого исходного кода останавливает применение адаптаций с
   ошибкой. Обновление оригинала идёт через отдельный PR, сборку и проверку
   устройства. Работающая установленная версия при этом сохраняется.
5. Снимок зависимостей переиспользуется при неизменном ключе входов. Изменение
   исходных Conan recipes/зависимостей может требовать новой подготовки образа;
   обновления панели её не запускают.

## Следующие продуктовые задачи

- При изменении формата --help или появлении принципиально новых методов
  адаптировать обнаружение возможностей; действующий формат поддержан в 0.11.0.
- Расширить поддерживаемые платформы и описание сборок за пределы проверенного
  mipsel-mips32r2-softfloat. Идентичность бинарника и отдельная версия оригинала
  реализованы в 0.12.0.
- Чистая установка/обновление/удаление из одного пакета для mipsel реализованы
  в 0.13.0; остаётся испытание чистой установки на устройстве и добавление других платформ.
- Исходящие соединения без gateway/via и смена WAN реализованы в 0.14.0;
  аппаратная проверка новой версии добровольная, автоматические проверки обязательны.
- Экспериментальная интеграция IPv6 реализована в 0.15.0 с сетевыми автотестами;
  DNS VPN остаётся отдельной будущей задачей.

Каждый пункт должен приводить к работе функции сервиса и не требует добавления
отдельной истории CPU/ОЗУ. Полного функционального равенства оригиналу пока нет;
эта таблица фиксирует имеющиеся ограничения вместо скрытых переключателей.
