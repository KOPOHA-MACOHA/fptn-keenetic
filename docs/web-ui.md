# Локальная панель FPTN

Адрес панели: `http://LAN_IP:PORT/`, где адрес и порт выбраны при установке (порт по умолчанию — 1111). Это отдельный слушающий адрес
существующего lighttpd, без дополнительного постоянно работающего веб-сервера.
Интерфейс адаптирован для телефона. Используется PHP без дополнительных расширений; Python на роутере не требуется.
Для состояния туннеля и проверки входа используется готовый клиент из каталога выбранного выпуска;
на роутере ничего не компилируется.

## Возможности

- Состояние процесса, READY при старте, RSS и журнал.
- Версии панели/ELF, текущий сервер и состояние туннеля из CLI.
- Кнопки управления доступны по структурированному состоянию службы.
- Изменения выделяются до применения; работающая служба получает кнопку
  «Применить и переподключить», остановленная — «Сохранить настройки».
- Проверка входа FPTN с результатом, миллисекундами и временем проверки.
  Она не создаёт TUN и не останавливает действующий клиент. Это не ICMP ping
  и не проверка передачи данных через VPN. Исключённые серверы не проверяются.
- Запуск, остановка, переподключение.
- Смена токена с чтением списка серверов; прежний токен не возвращается в браузер.
- Избранные и исключённые серверы, ручной и автоматический выбор.
- Одинарный, двойной и тройной rolling-туннель.
- Обфускация либо подмена SNI, профили Chrome/Firefox/Yandex/Safari из
  закреплённого upstream, ручной домен SNI.
- Сохранение параметров с перезапуском работающего клиента. Остановленный
  клиент после сохранения остаётся остановленным. При неудачном запуске
  выполняется попытка восстановления прежних файлов и запуска прежней конфигурации.

Маршрутизация и разрешение имён настраиваются вне панели. Необязательный
IPv6 NAT66 ограничен собственным интерфейсом; см. [описание IPv6](release-0.15.md). При установке автозапуск не включается; его можно включить кнопкой в панели. Состояние процесса/READY не является
проверкой доступа к сайтам или исправности живого WebSocket-соединения.
Автоматический поиск подходящего SNI не реализован; доступные методы
определяются по возможностям установленного клиента.

## Приоритеты и восстановление соединения

В автоматическом режиме сначала проверяются все разрешённые избранные.
Выбирается сервер с минимальным измеренным временем успешной авторизации.
Остальные серверы проверяются только если ни один избранный не авторизовался.
При пустом избранном проверяются все разрешённые. Это измерение входа, а не
тест максимальной скорости. Проверяется весь уровень, а не случайная половина.
Одновременно выполняются максимум две TLS-проверки; разрешено до 64 серверов.
Исключение действует до любого сетевого запроса и имеет приоритет над избранным
и ручным выбором. Настройку, исключающую все серверы, панель отклоняет.

В ручном режиме первым проверяется выбранный сервер, затем избранные и остальные.
После первого сохранения списков используется native-политика, даже в ручном режиме.
Если все каналы соединения недоступны непрерывно 15 секунд, CLI завершает текущую
сессию и supervisor запускает новый автоматический выбор. Обычное обновление
одного канала двойного/тройного туннеля и отсутствие трафика не являются обрывом.
Детектор использует состояние ConnectionManager через VpnManager::IsReconnecting.

Если сервер авторизовался, но DNS/туннель не запустился, он временно пропускается
в следующих попытках. Это отдельный runtime-список, не пользовательские исключения.
Через минуту жизни процесса временный список очищается; это сброс очереди попыток,
а не доказательство исправности соединения. Если все кандидаты исчерпаны после
ранее работавшего подключения, supervisor начинает новый проход с паузой 5–60 секунд.
При неудаче самого первого полного прохода start возвращает ошибку.
Первый запуск с политикой может ждать до 10 минут при большом числе недоступных
серверов. Операции UI асинхронны, страница и просмотр состояния продолжают работать.
`stop` прекращает выбор и повторы. В статусе показывается фактически выбранный сервер.

## Установка

Используйте [единый установщик](install.md) для новой установки, обновления
и удаления. LAN-адрес и порт панели сохраняются при обновлениях.
Файлы выпуска проверяются по контрольным суммам. Локальная компиляция не требуется.
Установка сохраняет учётные данные и конфигурацию; работающая служба
перезапускается при изменении клиента или supervisor, а при ошибке обновления
выполняется откат. Изменение только панели не требует перезапуска неизменённой службы.

## Файлы и диагностика

- `/opt/share/fptn-web/` — HTML/CSS/JS и CGI на POSIX shell.
- `/opt/etc/fptn/connection.json` — валидируемые bypass/strategy/sni, 0600.
- `/opt/etc/fptn/server-policy.json` — mode/favorites/excluded, 0600.
- `/opt/etc/fptn/token`, `server` — прежние пути, формат сохраняется.
- `/opt/etc/fptn/web-auth.json`, `web-origin` — доступ к панели, вне document-root.
- `/opt/etc/fptn/web-meta.json` — версия установленного ELF и SHA установки.
- `/opt/var/run/fptn-keenetic/link.json` — состояние соединения текущего процесса,
  пишется CLI только при изменении; supervisor проверяет PID/boot-id.
- `server-checks.json` в runtime службы или UI — отчёт входа без JWT/паролей.
  Используется наиболее свежий; смена параметров удаляет старый отчёт.
- `/opt/var/run/fptn-web/` — состояние асинхронной операции и её результат.
- `/opt/etc/fptn/web-recovery/` — прежние настройки после неудачного применения.

Смена настроек выполняется одним фоновым worker; параллельное действие
возвращает HTTP 409. Не выключайте питание во время применения настроек.
Операции 0.7 ведут журнал PID, времени запуска, boot-id и случайного
идентификатора. Если worker завершился, но его foreground-команда ещё работает,
восстановление недоступно. Постоянные процессы VPN/lighttpd не наследуют маркер
короткой операции. Панель не отправляет сигналов процессам при снятии блокировки.

Если процесс и его команды завершились, появляется «Восстановить управление».
Журнал и закрытые снимки архивируются в `web-recovery/ID`. При прерванном
применении настроек worker восстанавливает прежний токен, сервер, connection и
server-policy; при необходимости пытается вновь запустить службу. Неудача
подключения после восстановления настроек не блокирует дальнейшее управление.
Прерванное обновление требует повторить установку; путь к его резервной копии
сохраняется в журнале. Старую блокировку без журнала 0.7 нельзя автоматически
считать безопасной: она остаётся закрытой для восстановления через UI.

В разделе «Вход в панель» можно изменить логин/пароль отдельной учётной записи
или переключиться на root Entware и обратно. Обязателен текущий пароль; при
переключении на root также проверяется его существующий пароль. Пароль самого
root не меняется. После изменения все сессии отзываются; VPN не перезапускается.
Пароли не записываются в очередь операций или её архив.

Проверка локально: `sh -n`, `node --check`, реальные CGI-запросы через stdin с
реальным jq, файловой подменой клиента и без сетевого listener. Проверяются
аутентификация, Host/Origin, валидация, серверы Unicode, отсутствие токена в
ответах, блокировка операций, применение и откат после ошибки. Brotli в этих
тестах подменён; совместимость с настоящим декодером уже проверялась на роутере
в CLI. Реальный lighttpd, BusyBox и установка новой панели требуют проверки
на устройстве. Локальные тесты не заменяют эту проверку.

Node-тест исполняет настоящий app.js с подменой DOM и проверяет кнопки,
звёздочки/исключения, черновик настроек и версии. Docker запускает probe-only
под QEMU MIPS с закрытым loopback-портом и проверяет отчёт без TUN.

До замены клиента установщик проверяет новую страницу и auth-info по HTTP.
При ошибке веб-панели прежний VPN-клиент не останавливается, бинарник не меняется.
Ответы неудачной проверки сохраняются в закрытом backup/http-diagnostic;
они больше не теряются при очистке временной папки.

## Резервные методы подключения 0.8

Функция выключена по умолчанию. В параметрах подключения раскройте «Резервные
методы для избранных», выберите до двух SNI-профилей, до двух собственных SNI
и лимит 30/60/90/120 секунд. Нужны 1–8 разрешённых избранных. Это не поиск доменов
в интернете: выполняются реальные попытки FPTN только к серверам из токена.

В автоматическом режиме: последнее устойчивое сочетание (если ещё разрешено),
текущий метод на избранных, обфускация, выбранные SNI-профили/домены, затем
обычный выбор остальных серверов с исходными настройками. В ручном режиме
первым пробуется выбранный сервер; при восстановлении после потери устойчивого
соединения используется автоматический порядок. Исключения имеют приоритет.

Лимит относится к перебору на избранных, включая проверку текущего метода;
каждая попытка имеет свою долю лимита, некоторые варианты могут не успеть
провериться. Завершение CLI также занимает время; затем действует обычный
тайм-аут выбора остальных серверов. Одновременно работает один клиент и не
более двух проверок входа внутри него. При рабочем туннеле подбор не запускается.

После 60 секунд подтверждённого состояния connected запоминаются сервер/метод/SNI.
Потеря этого состояния сбрасывает счётчик.
Это не замер пропускной способности. Кэш привязан к токену и настройкам, не
содержит пароля или токена; смена настроек делает его неактуальным. Неудачные
результаты 401/403 из полного отчёта исключают сервер из оставшихся вариантов
текущего прохода. Незавершённый отчёт не трактуется как доказанная ошибка токена.

Сохранённые connection.json и стратегия туннелей не меняются автоматически.
В статусе показываются фактически применяемые метод и SNI; они могут отличаться
от исходных полей формы. Применение новых настроек, как раньше, переподключает
работающую службу. Маршруты, DNS и firewall остаются в Keenetic.


## Обновления из панели (0.9.0)

В разделе «Обновления» нажмите «Проверить обновления», затем «Установить обновление».
Каталог берётся только из `web/update.json` этого репозитория. Каталог указывает
закреплённый коммит, SHA-256 установщика и выпуск клиента. Каталог публикуется
после успешных проверок выпуска, а не указывает на каждое изменение main.
Проверка запускается только по кнопке; постоянного фонового опроса GitHub нет.

Установщик работает в отдельной фоновой операции. Он сохраняет резервную копию,
проверяет файлы и действительные ответы страницы/API после перезапуска lighttpd.
При ошибке выполняется откат файлов. Некорректный SHA-256, повреждённый каталог,
каталог старше суток или попытка понизить версию отклоняются до установки.
Сетевые маршруты, DNS и параметры входа не меняются. Клиент без необходимости
не перезапускается; при замене бинарника восстанавливается прежнее состояние службы.

При временной потере связи дождитесь восстановления панели. После успешного
обновления нажмите «Обновить страницу» в сообщении о несовпадении версий.
Принудительное выключение питания может прервать откат: журнал и путь к резервной
копии сохраняются для восстановления. Это не атомарное обновление прошивки.
Для первого перехода с 0.8.0 потребуется однократная установка команды с новым
установщиком; дальнейшие опубликованные выпуски доступны через браузер.


## MTU и исходящий интерфейс (0.10.0)

В дополнительных параметрах подключения MTU=0 использует действительный MTU
собственного OpkgTun. Старые настройки без mtu сохраняют это поведение. Явное значение
576–65535 применяется через ndmc только к интерфейсу FPTN при запуске;
при неудачном сохранении работающей конфигурации возвращается прежний фактический
MTU. Переход к 0 оставляет текущее значение Keenetic. Изменение startup-config
не требуется: явное значение повторно применяется службой после загрузки.

Исходящий интерфейс можно оставить пустым (обычный IPv4 default route) либо
указать системное имя, например eth2.2. Для него выбираются интерфейс и шлюз
из соответствующего IPv4 default/via в main. Если такого маршрута нет,
подключение завершается ошибкой вместо незаметного выбора другого интерфейса.
PPP/схемы без IPv4 via пока не поддержаны. Это выбор выхода транспорта FPTN,
не маршрутизация устройств LAN. Адреса, домены и CIDR по-прежнему задаются в Keenetic.


## Возможности установленного клиента (0.11.0)

Списки браузеров/профилей и стратегий формируются из --help действительного
бинарника. `fptnctl get-capabilities` возвращает JSON со списками, версией и SHA-256.
Это чтение не выполняет подключение и не получает токен. Сохранённые параметры
проверяются по тем же данным; произвольные неподдерживаемые методы не разрешаются.

Кэш находится в /opt/var/run/fptn-capabilities с правами root. Идентичность файла
проверяется через stat; при изменении перечитываются help/version и SHA-256.
Повторная загрузка настроек не запускает клиент и не пересчитывает SHA-256.
Время help/version ограничено, размер help ограничен; несовместимый вывод
завершает обнаружение ошибкой, не возвращая устаревшие возможности старого ELF.
Поддерживаются обфускация и SNI-методы стандартного вида sni-spoofing-BROWSER-VERSION,
а также имена стратегий rolling-tunnel / NAME-rolling-tunnel.

В резервных методах можно выбрать до двух любых доступных SNI-профилей.
Четыре прежних профиля переходят в соответствующие значения новых списков.
Если профиль исчез из обновлённого клиента, при выключенном подборе он виден
как недоступный и сохраняется до явного выбора пользователя. Включить подбор
с недоступным профилем нельзя. Первоначальные значения выбираются из актуальных
профилей разных браузеров, без фиксированных номеров версий.


## Проверяемая сборка клиента (0.12.0)

Для нового бинарника недостаточно изменить clientVersion. Подготовленный выпуск
содержит client-release.json с точным SHA-256, buildRevision, upstreamVersion,
upstreamRevision, sourceLockSha256 и platform. В workflow Build prototype после
проверки артефакта скрипт package-client-release.py формирует описание из самого
ELF, source lock и sources.upstream.json. Контрольные суммы артефакта проверяются
ещё раз перед созданием описания; clientVersion берётся из флага CMake в Dockerfile.

При подготовке проверенного выпуска описание копируется в корневой
client-release.json форка и включается package-web.py в манифест payload.
Каталог web/update.json получает clientSha256, upstreamVersion/upstreamRevision,
clientRevision и clientVersion из этого описания. Новые бинарники публикуются
в native-BUILD_SHA; обновление каталога остаётся отдельным действием после проверки.

Установщик сравнивает реальные байты установленного ELF с целевым SHA-256,
проверяет source lock и --version/--help. При совпадении SHA-256 новая копия ELF
не скачивается, даже если метаданные старой установки отсутствовали. Описание
старой установки восстанавливается при неудачном обновлении вместе с бинарником.
Сведения о текущем клиенте хранятся root-only в /opt/etc/fptn/client-release.json.

Панель показывает оригинальную версию только если кэш привязан к нынешнему файлу
и его SHA-256/версия совпадают с описанием установленной сборки. Статус использует
режим --cached: он не запускает клиент, не подключается и не читает весь ELF.
Если источник подтвердить нельзя, показывается «не определён» вместо версии
из произвольного текущего checkout. Бинарник при этом можно остановить/восстановить
обычными кнопками панели.
