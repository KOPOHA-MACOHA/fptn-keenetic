# Локальная панель FPTN

Адрес на Hopper: **http://192.168.1.1:1111/**. Это отдельный слушающий адрес
существующего lighttpd, без дополнительного постоянно работающего веб-сервера.
Интерфейс адаптирован для телефона. PHP и Python не требуются.
Для политики серверов используется готовый клиент 0.3.0; на роутере ничего не компилируется.

## Возможности первой версии

- Состояние процесса, READY при старте, RSS и журнал.
- Запуск, остановка, переподключение.
- Смена токена с чтением списка серверов; прежний токен не возвращается в браузер.
- Избранные и исключённые серверы, ручной и автоматический выбор.
- Одинарный, двойной и тройной rolling-туннель.
- Обфускация либо SNI + Reality, профили Chrome/Firefox/Yandex/Safari из
  закреплённого upstream, ручной домен SNI.
- Сохранение параметров с перезапуском работающего клиента. Остановленный
  клиент после сохранения остаётся остановленным. При неудачном запуске
  выполняется попытка восстановления прежних файлов и запуска прежней конфигурации.

Панель не настраивает маршруты, доменные списки, DNS или firewall. Это остаётся
в Keenetic. Автозапуск не включается. Состояние процесса/READY не является
проверкой доступа к сайтам или исправности живого WebSocket-соединения.
Автоподбор SNI в эту версию не входит: upstream реализует его в GUI,
а наш CLI не имеет команды сканирования. Декоративной кнопки нет.

## Приоритеты и восстановление соединения

В автоматическом режиме сначала проверяются все разрешённые избранные.
Выбирается сервер с минимальным измеренным временем успешной авторизации.
Остальные серверы проверяются только если ни один избранный не авторизовался.
При пустом избранном проверяются все разрешённые. Это измерение входа, а не
тест максимальной скорости. Проверяется весь уровень, а не случайная половина.
Одновременно выполняются максимум две TLS-проверки; разрешено до 64 серверов.
Исключение действует до любого сетевого запроса и имеет приоритет над избранным
и ручным выбором. Настройку, исключающую все серверы, панель отклоняет.

В ручном режиме первым проверяется выбранный сервер, затем избранные и остальные.
После первого сохранения списков используется native-политика, даже в ручном режиме.
Если все каналы соединения недоступны непрерывно 15 секунд, CLI завершает текущую
сессию и supervisor запускает новый автоматический выбор. Обычное обновление
одного канала двойного/тройного туннеля и отсутствие трафика не являются обрывом.
Детектор использует состояние ConnectionManager через VpnManager::IsReconnecting.

Если сервер авторизовался, но DNS/туннель не запустился, он временно пропускается
в следующих попытках. Это отдельный runtime-список, не пользовательские исключения.
Через минуту жизни процесса временный список очищается; это сброс очереди попыток,
а не доказательство исправности соединения. Если все кандидаты исчерпаны после
ранее работавшего подключения, supervisor начинает новый проход с паузой 5–60 секунд.
При неудаче самого первого полного прохода start возвращает ошибку.
Первый запуск с политикой может ждать до 10 минут при большом числе недоступных
серверов. Операции UI асинхронны, страница и просмотр состояния продолжают работать.
`stop` прекращает выбор и повторы. В статусе показывается фактически выбранный сервер.

## Установка

Нужны уже установленная native-служба FPTN, root-процесс lighttpd с mod_cgi,
его обычный Entware init-скрипт, curl/jq/ip/netstat/timeout и свободный TCP 1111.
Текущий конфиг lighttpd должен проходить `lighttpd -tt`.

Скачайте `scripts/install-web-ui.sh` из выбранного полного SHA коммита,
проверьте его SHA256 из сообщения о выпуске и выполните:

```sh
sh install-web-ui.sh install FULL_COMMIT_SHA
```

Необязательный третий аргумент — другой назначенный роутеру LAN IPv4.
Порт — 1111. При занятом чужом порте установщик прекращает работу до изменений.
Файлы берутся из того же закреплённого SHA и проверяются по `web/SHA256SUMS`.
Настройки общего listener lighttpd и чужие конфиги не редактируются.

Перед заменой создаётся закрытая резервная копия в
`/opt/etc/fptn/web-install-backup.XXXXXX`. Установщик обновляет fptnctl и
добавляет `/opt/etc/lighttpd/conf.d/95-fptn.conf`, проверяет конфиг,
перезапускает существующий lighttpd и проверяет страницу, отказ API без кода
и авторизованный запрос. Остальные веб-панели кратковременно недоступны при
этом перезапуске. При ошибке установщик пытается вернуть прежние файлы и
перезапустить lighttpd. Если ELF уже поддерживает политику серверов,
работающий клиент FPTN при установке UI не перезапускается.

Если установлен старый клиент без `--keenetic-server-policy`, установщик сначала
скачивает готовый ELF и SHA256SUMS из prerelease `native-FULL_COMMIT_SHA`, проверяет
контрольную сумму и запуск --help, сохраняет прежний ELF, затем останавливает FPTN,
атомарно заменяет бинарник и восстанавливает прежнее состояние службы. При ошибке
выполняется попытка отката бинарника и UI. Уже поддерживающий политику клиент
повторно не скачивается. Выпуск создаётся Actions после успешных probe и сборки CLI.
До завершения сборки и публикации новая установка с обновлением ELF невозможна.

В конце выводятся адрес и случайный код панели. Код можно заново прочитать
локально из `/opt/etc/fptn/web-key`; он не совпадает с токеном VPN.
При повторной установке этот код сохраняется. Браузер хранит его в
sessionStorage текущей вкладки; кнопка «Выйти» удаляет код из хранилища.

Панель слушает только выбранный LAN IPv4, без открытия WAN и изменения firewall.
API требует Bearer-код и правильный Host; запросы с чужим Origin запрещены.
Изменения принимаются только через POST JSON. Cookie-аутентификации нет.
Пользовательские строки передаются как данные и аргументы; `eval` и `source`
настроек не используются. Секреты и файлы действий находятся вне document-root.

## Файлы и диагностика

- `/opt/share/fptn-web/` — HTML/CSS/JS и CGI на POSIX shell.
- `/opt/etc/fptn/connection.json` — валидируемые bypass/strategy/sni, 0600.
- `/opt/etc/fptn/server-policy.json` — mode/favorites/excluded, 0600.
- `/opt/etc/fptn/token`, `server` — прежние пути, формат сохраняется.
- `/opt/etc/fptn/web-key`, `web-origin` — доступ к панели, вне document-root.
- `/opt/var/run/fptn-web/` — состояние асинхронной операции и её результат.
- `/opt/etc/fptn/web-recovery/` — прежние настройки после неудачного применения.

Смена настроек выполняется одним фоновым worker; параллельное действие
возвращает HTTP 409. Не выключайте питание во время применения настроек.
При аварийном завершении самого worker может остаться блокировка `action`;
автоматическое восстановление такой незавершённой операции пока не реализовано.
Не удаляйте её во время работы worker. Уточнение восстановления — отдельное
улучшение, не путать с уже реализованным перезапуском процесса клиента.

Проверка локально: `sh -n`, `node --check`, реальные CGI-запросы через stdin с
реальным jq, файловой подменой клиента и без сетевого listener. Проверяются
аутентификация, Host/Origin, валидация, серверы Unicode, отсутствие токена в
ответах, блокировка операций, применение и откат после ошибки. Brotli в этих
тестах подменён; совместимость с настоящим декодером уже проверялась на роутере
в CLI. Реальный lighttpd, BusyBox и установка новой панели требуют проверки
на устройстве. Локальные тесты не заменяют эту проверку.
