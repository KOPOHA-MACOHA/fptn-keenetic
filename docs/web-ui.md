# Локальная панель FPTN

Адрес на Hopper: **http://192.168.1.1:1111/**. Это отдельный слушающий адрес
существующего lighttpd, без дополнительного постоянно работающего веб-сервера.
Интерфейс адаптирован для телефона. PHP и Python не требуются.
Для состояния туннеля и проверки входа используется готовый клиент 0.4.0;
на роутере ничего не компилируется.

## Возможности первой версии

- Состояние процесса, READY при старте, RSS и журнал.
- Версии панели/ELF, текущий сервер и состояние туннеля из CLI.
- Кнопки управления доступны по структурированному состоянию службы.
- Изменения выделяются до применения; работающая служба получает кнопку
  «Применить и переподключить», остановленная — «Сохранить настройки».
- Проверка входа FPTN с результатом, миллисекундами и временем проверки.
  Она не создаёт TUN и не останавливает действующий клиент. Это не ICMP ping
  и не проверка передачи данных через VPN. Исключённые серверы не проверяются.
- Запуск, остановка, переподключение.
- Смена токена с чтением списка серверов; прежний токен не возвращается в браузер.
- Избранные и исключённые серверы, ручной и автоматический выбор.
- Одинарный, двойной и тройной rolling-туннель.
- Обфускация либо SNI + Reality, профили Chrome/Firefox/Yandex/Safari из
  закреплённого upstream, ручной домен SNI.
- Сохранение параметров с перезапуском работающего клиента. Остановленный
  клиент после сохранения остаётся остановленным. При неудачном запуске
  выполняется попытка восстановления прежних файлов и запуска прежней конфигурации.

Панель не настраивает маршруты, доменные списки, DNS или firewall. Это остаётся
в Keenetic. При установке автозапуск не включается; его можно включить кнопкой в панели. Состояние процесса/READY не является
проверкой доступа к сайтам или исправности живого WebSocket-соединения.
Автоподбор SNI в эту версию не входит: upstream реализует его в GUI,
а наш CLI не имеет команды сканирования. Декоративной кнопки нет.

## Приоритеты и восстановление соединения

В автоматическом режиме сначала проверяются все разрешённые избранные.
Выбирается сервер с минимальным измеренным временем успешной авторизации.
Остальные серверы проверяются только если ни один избранный не авторизовался.
При пустом избранном проверяются все разрешённые. Это измерение входа, а не
тест максимальной скорости. Проверяется весь уровень, а не случайная половина.
Одновременно выполняются максимум две TLS-проверки; разрешено до 64 серверов.
Исключение действует до любого сетевого запроса и имеет приоритет над избранным
и ручным выбором. Настройку, исключающую все серверы, панель отклоняет.

В ручном режиме первым проверяется выбранный сервер, затем избранные и остальные.
После первого сохранения списков используется native-политика, даже в ручном режиме.
Если все каналы соединения недоступны непрерывно 15 секунд, CLI завершает текущую
сессию и supervisor запускает новый автоматический выбор. Обычное обновление
одного канала двойного/тройного туннеля и отсутствие трафика не являются обрывом.
Детектор использует состояние ConnectionManager через VpnManager::IsReconnecting.

Если сервер авторизовался, но DNS/туннель не запустился, он временно пропускается
в следующих попытках. Это отдельный runtime-список, не пользовательские исключения.
Через минуту жизни процесса временный список очищается; это сброс очереди попыток,
а не доказательство исправности соединения. Если все кандидаты исчерпаны после
ранее работавшего подключения, supervisor начинает новый проход с паузой 5–60 секунд.
При неудаче самого первого полного прохода start возвращает ошибку.
Первый запуск с политикой может ждать до 10 минут при большом числе недоступных
серверов. Операции UI асинхронны, страница и просмотр состояния продолжают работать.
`stop` прекращает выбор и повторы. В статусе показывается фактически выбранный сервер.

## Установка

Нужны уже установленная native-служба FPTN, root-процесс lighttpd с mod_cgi,
его обычный Entware init-скрипт, curl/jq/ip/netstat/timeout и свободный TCP 1111.
Текущий конфиг lighttpd должен проходить `lighttpd -tt`.

Скачайте `scripts/install-web-ui.sh` из выбранного полного SHA коммита,
проверьте его SHA256 из сообщения о выпуске и выполните:

```sh
sh install-web-ui.sh install FULL_COMMIT_SHA
```

Необязательный третий аргумент — другой назначенный роутеру LAN IPv4.
Четвёртый — необязательный SHA уже опубликованного бинарника, если UI/controller исправляются
отдельным коммитом без пересборки ELF. Например, клиент 0.4.0 опубликован для
`c0386cbb73bf9ddf35e551c08d094ac0debf2466` (уже выбран по умолчанию).
Порт — 1111. При занятом чужом порте установщик прекращает работу до изменений.
Файлы берутся из того же закреплённого SHA и проверяются по `web/SHA256SUMS`.
Настройки общего listener lighttpd и чужие конфиги не редактируются.

Перед заменой создаётся закрытая резервная копия в
`/opt/etc/fptn/web-install-backup.XXXXXX`. Установщик обновляет fptnctl и
добавляет `/opt/etc/lighttpd/conf.d/95-fptn.conf`, проверяет конфиг,
перезапускает существующий lighttpd и проверяет страницу, отказ API без кода
и авторизованный запрос. Остальные веб-панели кратковременно недоступны при
этом перезапуске. При ошибке установщик пытается вернуть прежние файлы и
перезапустить lighttpd. Если ELF уже поддерживает диагностику,
работающий клиент FPTN при установке UI не перезапускается.

Если установлен старый клиент без `--keenetic-probe-only`, установщик сначала
скачивает готовый ELF и SHA256SUMS из prerelease `native-FULL_COMMIT_SHA`, проверяет
контрольную сумму и запуск --help, сохраняет прежний ELF, затем останавливает FPTN,
атомарно заменяет бинарник и восстанавливает прежнее состояние службы. При ошибке
выполняется попытка отката бинарника и UI. Уже поддерживающий диагностику клиент
повторно не скачивается. Выпуск создаётся Actions после успешных probe и сборки CLI.
До завершения сборки и публикации новая установка с обновлением ELF невозможна.

Ненулевой код init-скрипта lighttpd сам по себе не вызывает откат.
После restart установщик около 30 секунд ожидает настоящую готовность панели:
правильную версию HTML, HTTP 401 для API без сессии и корректный
`auth-info` новой версии. Отсроченный запуск после `failed` считается успешным,
если эти проверки проходят. Сам факт существования процесса недостаточен.
Отказ ответа или неверная версия после ожидания приводит к обычному откату.

Остановка выполняется проверенным controller из загруженного пакета, чтобы
исправление могло остановить старый supervisor. PID проверяется по boot-id,
времени запуска и исполняемому файлу; клиент с заменённым `(deleted)` ELF тоже
распознаётся. Ожидание ограничено. SIGKILL supervisor допускается только после
завершения клиента и проверки принадлежности shell этой службе.
При отказе первой остановки файлы не заменяются и откат не вызывается повторно.
Установщик занимает блокировку UI на время изменения файлов, чтобы запуск
через панель не пересёкся с заменой бинарника. Откат использует отдельные признаки
реальной замены ELF и попытки запуска нового клиента.

Установщик не запрашивает пароль. На первом открытии браузер показывает выбор:

- создать отдельный логин/пароль панели, подтвердить пароль, затем войти;
- использовать существующий пароль **root Entware** и сразу войти.

Используется уже установленный PHP (`php-cgi` от nfqws/lighttpd). Отдельный
OpenSSL не нужен; дополнительные процессы демонов не запускаются.
Проверка root повторяет подход nfqws-keenetic-web: `/opt/etc/shadow`, а при
его отсутствии `/opt/etc/passwd`, PHP `crypt()` и `hash_equals()`.
Заблокированный/пустой пароль root не принимается. FPTN не меняет пользователей,
не сохраняет пароль root и не читает пароль пользователя KeeneticOS.

Отдельный пароль панели хранится как bcrypt (cost 10), файл root-only.
Непустой пароль до 72 байт задаёт пользователь; произвольного минимума 10 нет.
Первичное создание блокируется после сохранения учётной записи, включая
конкурентные запросы. Существующие SHA-512 crypt учётные записи 0.5 сохраняются
и проверяются PHP, без зависимости от openssl.

Сессия действует 12 часов; браузер хранит её в sessionStorage, сервер — только
хеш идентификатора и отпечаток настроек входа. Выход и изменение пароля root
отзывают прежние сессии. Пять неудачных попыток дают паузу 30 секунд.
Проверка пароля производится только при входе. Блокировка PHP `flock`
снимается ядром даже при аварийном завершении процесса.

Для восстановления доступа root может выполнить `fptnctl web-reset-login`:
это сбрасывает только вход FPTN, после чего снова доступен первый экран в
браузере. VPN-токен и пароль Entware не меняются.
Панель остаётся HTTP в LAN; вход по паролю не шифрует транспорт.

Автозапуск: `fptnctl enable` / `disable` или кнопка панели. Управляемый
`/opt/etc/init.d/S90fptn` запускает supervisor без ожидания READY при загрузке.
Интерфейс OpkgTun0 должен быть сохранён в startup-config Keenetic.
При недоступном интернете загрузочный запуск повторяется с паузой 5–60 секунд.
Отключение автозапуска не останавливает текущее подключение. Установщик сохраняет
выбранный режим; чужой S90fptn не перезаписывается.

Входная страница — статический index.html; Cache-Control: no-store задаётся
в vhost lighttpd через mod_setenv. index.cgi оставлен как независимый от PATH
резервный обработчик. Отсутствие заголовка у ещё не перезагруженного сервера
даёт предупреждение со свежей ссылкой, а не откат рабочей панели. JS/CSS имеют
версию в query string. Для перехода со старой закэшированной панели используйте
адрес установщика с `?v=COMMIT`. Он проверяет версии HTML/API и наличие no-store.
UI предупреждает о несовпадении версии страницы и API.

Панель слушает только выбранный LAN IPv4, без открытия WAN и изменения firewall.
API требует временную Bearer-сессию и правильный Host; запросы с чужим Origin запрещены.
Изменения принимаются только через POST JSON. Cookie-аутентификации нет.
Пользовательские строки передаются как данные и аргументы; `eval` и `source`
настроек не используются. Секреты и файлы действий находятся вне document-root.

## Файлы и диагностика

- `/opt/share/fptn-web/` — HTML/CSS/JS и CGI на POSIX shell.
- `/opt/etc/fptn/connection.json` — валидируемые bypass/strategy/sni, 0600.
- `/opt/etc/fptn/server-policy.json` — mode/favorites/excluded, 0600.
- `/opt/etc/fptn/token`, `server` — прежние пути, формат сохраняется.
- `/opt/etc/fptn/web-auth.json`, `web-origin` — доступ к панели, вне document-root.
- `/opt/etc/fptn/web-meta.json` — версия установленного ELF и SHA установки.
- `/opt/var/run/fptn-keenetic/link.json` — состояние соединения текущего процесса,
  пишется CLI только при изменении; supervisor проверяет PID/boot-id.
- `server-checks.json` в runtime службы или UI — отчёт входа без JWT/паролей.
  Используется наиболее свежий; смена параметров удаляет старый отчёт.
- `/opt/var/run/fptn-web/` — состояние асинхронной операции и её результат.
- `/opt/etc/fptn/web-recovery/` — прежние настройки после неудачного применения.

Смена настроек выполняется одним фоновым worker; параллельное действие
возвращает HTTP 409. Не выключайте питание во время применения настроек.
Операции 0.7 ведут журнал PID, времени запуска, boot-id и случайного
идентификатора. Если worker завершился, но его foreground-команда ещё работает,
восстановление недоступно. Постоянные процессы VPN/lighttpd не наследуют маркер
короткой операции. Панель не отправляет сигналов процессам при снятии блокировки.

Если процесс и его команды завершились, появляется «Восстановить управление».
Журнал и закрытые снимки архивируются в `web-recovery/ID`. При прерванном
применении настроек worker восстанавливает прежний токен, сервер, connection и
server-policy; при необходимости пытается вновь запустить службу. Неудача
подключения после восстановления настроек не блокирует дальнейшее управление.
Прерванное обновление требует повторить установку; путь к его резервной копии
сохраняется в журнале. Старую блокировку без журнала 0.7 нельзя автоматически
считать безопасной: она остаётся закрытой для восстановления через UI.

В разделе «Вход в панель» можно изменить логин/пароль отдельной учётной записи
или переключиться на root Entware и обратно. Обязателен текущий пароль; при
переключении на root также проверяется его существующий пароль. Пароль самого
root не меняется. После изменения все сессии отзываются; VPN не перезапускается.
Пароли не записываются в очередь операций или её архив.

Проверка локально: `sh -n`, `node --check`, реальные CGI-запросы через stdin с
реальным jq, файловой подменой клиента и без сетевого listener. Проверяются
аутентификация, Host/Origin, валидация, серверы Unicode, отсутствие токена в
ответах, блокировка операций, применение и откат после ошибки. Brotli в этих
тестах подменён; совместимость с настоящим декодером уже проверялась на роутере
в CLI. Реальный lighttpd, BusyBox и установка новой панели требуют проверки
на устройстве. Локальные тесты не заменяют эту проверку.

Node-тест исполняет настоящий app.js с подменой DOM и проверяет кнопки,
звёздочки/исключения, черновик настроек и версии. Docker запускает probe-only
под QEMU MIPS с закрытым loopback-портом и проверяет отчёт без TUN.

До замены клиента установщик проверяет новую страницу и auth-info по HTTP.
При ошибке веб-панели прежний VPN-клиент не останавливается, бинарник не меняется.
Ответы неудачной проверки сохраняются в закрытом backup/http-diagnostic;
они больше не теряются при очистке временной папки.
