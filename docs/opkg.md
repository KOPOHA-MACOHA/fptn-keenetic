# Установка пакетом Entware

> Проект экспериментальный. Установка и использование — на свой страх и риск.
> Аппаратные испытания проводились только на Keenetic Hopper KN-3810.
> CI и QEMU не подтверждают работу на всех моделях.

## Автоматическая установка

Entware, KeeneticOS и компонент TUN должны быть установлены заранее.

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/install.sh | sh -s opkg
```

Для другого LAN IPv4 или явного порта:

```sh
curl -fsSL https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/install.sh | sh -s opkg 192.168.10.1 1115
```

Bootstrap ставит недостающие общие зависимости, регистрирует только собственный
feed и вызывает `opkg install fptn-keenetic`. Первоначальный порт выбирается в
терминале; без терминала проверяется 1111. При конфликте установка сообщает
ошибку, а уже работающий сервис сохраняется. Повтор настройки пакета:

```sh
fptn-package configure 192.168.10.1 1115
```

Новый интерфейс выбирается среди свободных OpkgTun. Настройки подключения,
учётную запись и автозапуск задают в панели. Пакет не включает VPN автоматически.
Общие зависимости и начальный listener нового root-lighttpd готовятся так же,
как в обычном bootstrap. Ранее настроенный общий веб-сервер не перенастраивается.

## Ручная установка

Можно скачать `.ipk` из [Releases](https://github.com/KOPOHA-MACOHA/fptn-keenetic/releases),
выбрав архитектуру Entware:

| Сборка | Architecture пакета | Feed |
| --- | --- | --- |
| MIPS little-endian soft-float | `mipsel-3.4` | `entware-feed-mipselsf-k3.4` |
| ARM64 | `aarch64-3.10` | `entware-feed-aarch64-k3.10` |
| ARMv7 soft-float | `armv7-3.2` | `entware-feed-armv7sf-k3.2` |

Установите скачанный файл командой `opkg install /путь/к/файлу.ipk`.
Opkg разрешает зависимости из ваших существующих Entware feeds. Для пакетных
обновлений зарегистрируйте соответствующий feed либо один раз запустите
автоматическую команду выше: повторная установка сохраняет настройки.
Автоматический выбор платформы не заменяет проверки модели/ISA; неизвестные
архитектуры установщик отвергает.

Прежние способы — обычный bootstrap `install.sh install` и полный `.tar.gz` —
остаются доступными: см. [установку](install.md). Переход с такой установки на
`.ipk` сохраняет настройки и выбранный интерфейс. Обратное смешивание установщиков
блокируется: сначала удалите пакет, сохранив конфигурацию.

## Обновление и удаление

```sh
opkg update
opkg upgrade fptn-keenetic
```

Обновление из панели для пакетной установки использует эти же операции.
Прямой установщик не перезаписывает управляемую opkg установку. Токен, параметры,
вход, избранные, исключения, выбранный порт и интерфейс сохраняются. Замена клиента
и supervisor использует существующую транзакцию с откатом. Неуспешный postinst
оставляет пакет не настроенным; исправьте указанную причину и выполните
`opkg configure fptn-keenetic` либо `fptn-package configure LAN_IP PORT`.

```sh
opkg remove fptn-keenetic
```

`fptnctl uninstall` также передаёт удаление opkg. Сначала штатный деинсталлятор
останавливает собственные процессы и проверяет владение файлами. Если удалить
их безопасно нельзя, `prerm` завершается ошибкой и opkg не удаляет payload.
Удаление не затрагивает общие пакеты, токен/вход/настройки в `/opt/etc/fptn`,
сам OpkgTun и связанные маршруты Keenetic. Если переход с ручной установки
не завершился, удаление ненастроенного пакета сохраняет прежний ручной runtime.

## Устройство пакета и границы проверки

Opkg владеет управляющим скриптом и неизменяемым runtime-payload в
`/opt/share/fptn-package`. Развёрнутыми файлами службы и панели управляет общий
транзакционный установщик и его реестр владения. Это позволяет использовать
одинаковые проверки/откат для обоих способов установки. Не удаляйте payload
вручную: он нужен для повторной конфигурации без загрузки клиента.

Компрессированный payload остаётся на накопителе: примерно ещё один размер
скачанного `.ipk` сверх развёрнутого клиента; временно требуется место для
распаковки и резервной копии. Дополнительных фоновых процессов и постоянного
сборщика метрик пакет не добавляет. Сборка `.ipk` использует готовые бинарники;
Conan и компилятор на роутер не устанавливаются.

Версия пакета — версия панели и монотонный номер коммита runtime, например
`0.18.4-200`; версия C++ клиента указывается отдельно. Публикуются только пакеты
из прошедшего проверки runtime. Перед изменением индексов проверяются SHA-256,
архитектуры, версии и источник; откат feed на меньшую версию запрещён.
Индексы обслуживаются по HTTPS с SHA-256 пакетов. Независимой подписи feed пока
нет; глобальные настройки проверки подписей opkg установщик не отключает.
Если ваша конфигурация требует такую подпись, этот feed ей не соответствует.

CI проверяет формат и реальные операции native opkg в offline-root, а жизненный
цикл deployment — в изолированных моделях сервисов. Это не аппаратная установка
на роутер. Принудительные `--force-*` опции opkg не нужны для обычной установки
и обходят часть предусмотренной защиты.
