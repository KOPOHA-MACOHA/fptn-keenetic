# Интеграция FPTN со штатным TUN Keenetic

FPTN обслуживает VPN-транспорт, а KeeneticOS владеет выбранным интерфейсом OpkgTun.
Маршрутизация настраивается вне FPTN; конкретная схема сети и сторонний менеджер
маршрутов не требуются. Экспериментальный IPv6 может отдельно использовать
собственную ограниченную цепочку NAT66; по умолчанию эта функция выключена.

## Требования

Нужны KeeneticOS с поддержкой OpkgTun, Entware и `/dev/net/tun`.
При новой установке выбирается первый свободный номер: OpkgTun0, OpkgTun1 и далее.
Учитываются и объекты Keenetic, и устройства Linux. Например, OpkgTun3 соответствует
`opkgtun3` в Linux. Имя сохраняется в `/opt/etc/fptn/native-interface` и используется
клиентом, службой, панелью, MTU и необязательным IPv6. Обновление и повторная установка
не выбирают новый номер. Чужие интерфейсы не присваиваются FPTN.

## Создание интерфейса

Для обычной установки используйте [единый установщик и панель](install.md).
Установщик создаёт собственный интерфейс автоматически. Для восстановления
незавершённой настройки доступна кнопка панели либо команда:

```sh
fptnctl setup-interface
```

Первичная конфигурация: описание FPTN, уровень безопасности public,
IPv4 `10.0.0.1/32`, MTU 1420, TCP MSS adjustment и состояние up.
Устанавливается `no ip global`: интерфейс не назначается общим выходом в интернет.
Уже настроенный собственный интерфейс при повторном вызове не перезаписывается.

Сохранение конфигурации Keenetic выполняется отдельно:

```sh
ndmc -c 'system configuration save'
```

Команда сохраняет всю текущую конфигурацию Keenetic, включая другие несохранённые
изменения. Затем необходимые назначения направляются через выбранный OpkgTun средствами
выбранной внешней конфигурации маршрутизации.

## Владение устройством

Клиент с флагами `--keenetic-connect --keenetic-native` подключает файловый дескриптор
к существующему устройству через TUNSETIFF. Проверяются ifindex, IPv4, MTU и IFF_UP;
поддерживаются TUN и MULTI_QUEUE. Клиент не переименовывает устройство,
не вызывает TUNSETPERSIST и не меняет его адреса, MTU или флаги через TUN driver.

Явно заданный MTU применяется службой только к принадлежащему FPTN интерфейсу
через ndmc. В режиме «Как в Keenetic» текущее значение читается без изменения.
[Необязательный IPv6](release-0.15.md) использует отдельную настройку адреса
через ndmc и ограниченный собственным интерфейсом NAT66.

## Жизненный цикл

`start` запускает клиент и supervisor. `stop` завершает собственные процессы и
закрывает собственный дескриптор; постоянный интерфейс прошивки и внешние маршруты
сохраняются. Переключатель интерфейса Keenetic не заменяет управление службой FPTN.
Автозапуск включается отдельно через панель или `fptnctl enable`.

Supervisor контролирует текущее состояние соединения, повторяет подключение
с ограниченной паузой и поддерживает политику избранных/исключённых серверов.
Потеря WAN и изменение исходящего подключения обрабатываются отдельно от отказа
VPN-сервера. [Подробности WAN/PPPoE](release-0.14.md) и [параметры панели](web-ui.md).

## Обновление и удаление

Панель использует проверяемые выпуски, сохраняет настройки и выполняет откат при
ошибке обновления. Ручное копирование ELF из временных каталогов не требуется.
Удаление программы сохраняет интерфейс и внешнюю маршрутизацию; см. [установку](install.md).
