# Служба 0.15.0: экспериментальная передача IPv6 устройств LAN

IPv6 включается отдельно в дополнительных параметрах, по умолчанию выключен.
Нужны IPv6 в локальной сети Keenetic, ip6tables Entware, IPv6 NAT в ядре и MTU
от 1280. Отсутствие компонента приводит к отказу проверки настроек, а не к
молчаливому обходу VPN. Ничего автоматически не устанавливается на роутер.

Почему необходим NAT66: оригинальный FPTN выдаёт клиенту один IPv6-адрес.
При отправке WebSocket-клиент заменяет source на выданный адрес, а при получении
пакетов destination на адрес TUN. Для возвращения ответов нескольким устройствам
LAN нужна таблица соединений. Используется ядро Linux, без собственного NAT
в C++ и без изменения протокола FPTN.

При включении добавляется только адрес `fd42:6670:746e::1/128` к принадлежащему
FPTN OpkgTun0 через ndmc. Отдельная цепочка `FPTN_KN_6` делает SNAT только
пакетов, которые штатная маршрутизация уже направила в `opkgtun0`.
Маршруты по доменам/CIDR, общий выход, DNS, объявления IPv6 в LAN, правила FORWARD
и другие интерфейсы не меняются. MTU ниже 1280 не принимается.

Файл `/opt/etc/ndm/netfilter.d/190-fptn-ipv6.sh` восстанавливает собственную цепочку
после пересборки firewall Keenetic, только пока служба работает и IPv6 включён.
Hook только передаёт запрос supervisor; правила применяет сам supervisor после
READY и при следующем проходе мониторинга. Hook не конкурирует с остановкой и
не ждёт iptables внутри пересборки NDM.
При остановке цепочка удаляется. Чужая цепочка с таким именем не присваивается;
неизвестные правила в собственной цепочке не очищаются автоматически.

Собственный IPv6-адрес удаляется при следующем запуске с выключенным IPv6.
Уже существовавший адрес не удаляется как собственный. Интерфейс и firmware-маршруты
при остановке/удалении программы остаются, как и для IPv4.

Автотесты проверяют реальные IPv6 TCP-запрос/ответ из отдельной LAN namespace,
SNAT и conntrack обратного трафика, повторное применение, восстановление после
пересоздания цепочки и сохранение посторонних правил. Отдельные проверки моделируют
ndmc, отказ настройки и возврат к IPv4. Эти проверки не являются подключением
к реальному FPTN-серверу по IPv6 и не подтверждают поддержку NAT66 ядром каждой
модели Keenetic. Возможность поэтому помечена экспериментальной и не включается
при обновлении автоматически.

Также добавлена ускоренная проверка 20 последовательных DHCP-переподключений:
один supervisor, смена дочернего PID, ограничение RSS/дескрипторов и отсутствие
оставшихся дочерних процессов. Это тест жизненного цикла, не испытание месячной
работы с живым сервером и реальным трафиком.

Установщик применяет изменение supervisor сразу: работающая служба
перезапускается даже при неизменном клиентском ELF. Обновление только панели
или метаданных не прерывает неизменённую службу. Отказ нового supervisor
возвращает прежнюю программу и состояние без ненужной замены бинарника.

Готовые установочные архивы выпускаются для mipsel MIPS32r2 soft-float,
ARM64 и ARMv7 EABI5 soft-float. ARM-сборки проходят ELF/ABI, C++20 runtime,
CLI и probe-only под QEMU; Brotli — сжатие/распаковку. Аппаратного подключения
на ARM не заявлено. Установщик и обновления выбирают точные клиент и декодер
из каталога архитектур; чужой или отсутствующий пакет не подставляется.
Транспортные адаптеры и исходный протокол общие, SDK и кэш зависимостей отдельные.
