# FPTN для Keenetic / Entware

Исследовательский проект интеграции [FPTN](https://github.com/fptn-project/fptn)
с KeeneticOS и Entware: кросс-сборка, совместимость платформ, VPN-клиент,
управляемая служба и локальная веб-панель. Это не официальный выпуск FPTN или Keenetic.
Проект не предоставляет серверы, подписки или доступ к VPN-сервисам.

> **Экспериментальное ПО. Установка и использование — на свой страх и риск.**
> Аппаратные испытания проводились только на **Keenetic Hopper (KN-3810)**.
> Работа на других моделях не подтверждена; сборка, CI и QEMU не заменяют
> аппаратных испытаний. Возможны потеря связи, ошибки настройки и простои.
> Перед установкой сохраните резервную копию конфигурации и возможность
> локального доступа к роутеру. Гарантии работоспособности и безопасности не предоставляются.
>
> [Назначение проекта, условия использования и юридические оговорки](DISCLAIMER.md).

## Возможности

- Импорт токена, список серверов, ручной и автоматический выбор.
- Избранные и исключённые серверы, резервные методы подключения.
- Обфускация и доступные в клиенте браузерные профили подмены SNI.
- Одинарный, двойной и тройной скользящие туннели.
- Автозапуск, восстановление соединения, ожидание сети и смена WAN.
- Управление MTU собственного интерфейса и исходящим подключением.
- Установка, обновление и удаление; резервная копия и откат при ошибке обновления.
- Локальная панель с отдельной учётной записью или входом через root Entware.

FPTN обслуживает туннель через штатный интерфейс **OpkgTun**. Выбор трафика, направляемого
в туннель, определяется внешней конфигурацией маршрутизации. Проект не требует
определённого стороннего менеджера маршрутов или единой схемы домашней сети.
Экспериментальная передача IPv6 включается отдельно и по умолчанию выключена.

## Требования и платформы

Нужны KeeneticOS с поддержкой OpkgTun, Entware и устройство `/dev/net/tun`.
Пакеты содержат статические musl-бинарники; системные glibc и libstdc++ не заменяются.

| Архитектура | Установочный архив |
| --- | --- |
| MIPS32r2 little-endian, o32, soft-float | `fptn-keenetic-mipsel-mips32r2-softfloat.tar.gz` |
| ARM64, ARMv8-A little-endian | `fptn-keenetic-aarch64.tar.gz` |
| ARMv7-A little-endian, EABI5, soft-float | `fptn-keenetic-armv7-softfloat.tar.gz` |

Совпадение архитектуры не гарантирует совместимость каждой модели.
**В текущем выпуске требуется свободный OpkgTun0.** Если он занят другим
приложением, установка откажется продолжать; следующий свободный номер
автоматически не выбирается. Это ограничение реализации, а не требование KeeneticOS.
[Требования ABI и границы проверки](docs/platforms.md).

## Установка и управление

Запустите одну команду в SSH-консоли Entware от root. Требуется `curl`:

```sh
(
  set -eu
  fptn_setup=$(mktemp -d)
  trap 'rm -rf "$fptn_setup"' EXIT
  curl --proto '=https' --proto-redir '=https' -fLsS --connect-timeout 15 --max-time 120 \
    https://raw.githubusercontent.com/KOPOHA-MACOHA/fptn-keenetic/main/install.sh \
    -o "$fptn_setup/install.sh"
  sh "$fptn_setup/install.sh" install
)
```

Команда сама загружает установщик с GitHub, а установщик выбирает опубликованный
клиент для архитектуры Entware и скачивает необходимые файлы. Контрольные суммы
проверяются **автоматически**; вручную скачивать архивы, распаковывать их и сверять
SHA256 не требуется. При ошибке загрузки установка не запускается.

По умолчанию используется LAN-адрес `192.168.1.1`, панель — `http://192.168.1.1:1111/`.
Для другого адреса добавьте его после `install` в последней строке команды.
Токен, сервер и вход задаются в браузере. Автозапуск включается отдельно.
На роутере ничего не компилируется; устанавливаются только недостающие зависимости Entware.

[Подробная установка, обновление и удаление](docs/install.md).
Полные архивы из [выпусков](https://github.com/KOPOHA-MACOHA/fptn-keenetic/releases)
остаются дополнительным способом установки.

```sh
fptnctl status          # состояние службы и выбранный сервер
fptnctl start           # запуск с сохранёнными параметрами
fptnctl stop            # остановка с сохранением интерфейса и маршрутов
fptnctl enable          # включить автозапуск
fptnctl disable         # выключить автозапуск без остановки текущего соединения
fptnctl logs            # журнал службы
fptnctl web-reset-login # сбросить вход в панель
fptnctl uninstall       # удалить программу, сохранив конфигурацию
```

## Обновления и исходники

Транспорт, авторизация, TLS и форматы пакетов остаются в оригинальном FPTN.
`sources.lock.json` закрепляет исходники и зависимости, а небольшие адаптеры
добавляют интеграцию с Keenetic. Изменение ожидаемой структуры исходников
останавливает сборку вместо молчаливого применения несовместимой адаптации.

Проверка новых стабильных версий оригинала создаёт отдельный PR со сборкой и
автотестами. Автоматического merge или установки upstream на роутер нет.
Обновления опубликованных пакетов устанавливаются через панель с проверкой
контрольных сумм и совместимости сохранённых настроек.

## Сборка и проверки

Для локальной кросс-сборки нужен Docker BuildKit на Linux x86_64:

```sh
docker build --target probe-export --output type=local,dest=out/probe .
docker build --target client-export --output type=local,dest=out/client .
```

ARM-профили и закреплённые SDK описаны в [документации платформ](docs/platforms.md).
В GitHub Actions проверяются ABI ELF, выполнение CLI и C++20-проб под QEMU,
жизненный цикл службы, установка и откат, веб-панель и изолированные сетевые сценарии.
Эмуляция и автотесты не подтверждают реальную скорость, длительную стабильность
или поддержку конкретной модели. Проект имеет экспериментальный статус.

При использовании HTTPS-прокси сертификат CA можно передать в BuildKit через
`--secret id=proxy_ca,src=/path/to/ca-bundle.pem`; он не включается в артефакты.
