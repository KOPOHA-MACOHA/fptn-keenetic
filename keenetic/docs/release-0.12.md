# Панель и служба 0.12.0

Обновление бинарника определяется по закреплённому SHA-256, а не только по
номеру версии. Разные сборки с версией 0.4.0 будут различаться; совпадающие
байты повторно не скачиваются и не требуют перезапуска службы.

`client-release.json` описывает платформу, версию клиента Keenetic, коммит
сборки, SHA-256 ELF, версию/коммит оригинального FPTN и SHA-256 source lock.
Описание входит в проверяемый манифест файлов панели. Каталог обновлений
также передаёт идентичность клиента; прежний updater может установить этот
выпуск, поскольку установщик читает описание из закреплённого коммита.

Перед запуском проверяются SHA-256, версия, source lock и возможности бинарника.
Откат восстанавливает прежний ELF, source lock, контрольные суммы, сведения о
клиенте и прежнюю панель. Если служба была запущена, предпринимается её запуск
с восстановленным клиентом; внешний сбой сети не позволяет гарантировать
подключение даже с прежней версией. Остановленная служба остаётся остановленной.

Панель показывает свои версию, версию клиента Keenetic и версию исходного FPTN
отдельно. Оригинальная версия подтверждается только при совпадении записи
с действительным бинарником. Опрос статуса читает уже проверенный кэш и не
выполняет --help/--version или полное хеширование ELF.

MTU в интерфейсе обозначается «Как в Keenetic» с текущим значением либо задаётся
вручную. В оригинальном FPTN значение по умолчанию 1420; внутренний 0 сохраняется
только в JSON как режим использования MTU Keenetic, без изменения формата настроек.

Выпуск использует прежний проверенный ELF 0.4.0 (исходный FPTN 0.4.6).
Компиляция клиента/зависимостей не нужна. Обновление проверяется тестами с
подменами клиента/сети и на Linux lighttpd/PHP; такие проверки не подтверждают совместимость каждой модели.
